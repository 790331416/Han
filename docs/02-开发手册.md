## 1. 基础环境与推荐命令

- JDK 21

- Docker 26+

固定路径：

| 工具 | 固定路径 |

| JDK 21 | `D:\Program Files\Java\jdk-21.0.10` |
| Maven | `D:\Program Files\apache-maven-3.9.12` |
| Node.js | `D:\Program Files\nodejs` |
| pnpm | `D:\Program Files\nodejs\node_modules\corepack\shims\pnpm.cmd` |

## 2. 技术栈强制约束

本节吸收了历史开发规范中的技术禁令，但只保留当前仓库实际执行的正式口径。

### 2.1 JSON 处理

- 必须优先使用 Jackson
- 禁止新增 Gson、Fastjson、Fastjson2 依赖
- 敏感字段通过 `@JsonIgnore`、自定义序列化器或 VO 层隔离

### 2.2 服务间调用

- 必须优先使用 `@HttpExchange` 声明式客户端
- 禁止新增 Feign
- 不鼓励新增 `RestTemplate` 风格客户端

当前已落地示例：

- [SystemServiceClient.java](../han-api/han-api-system/src/main/java/com/han/api/system/SystemServiceClient.java)
- [TenantServiceClient.java](../han-api/han-api-tenant/src/main/java/com/han/api/tenant/TenantServiceClient.java)
- [FileServiceClient.java](../han-api/han-api-file/src/main/java/com/han/api/file/FileServiceClient.java)

### 2.3 对象映射

- 新增 PO / DTO / VO 转换优先使用 MapStruct
- 禁止新增 `BeanUtils.copyProperties` 作为正式转换方案
- 需要兼容旧代码时，应优先在 Converter 层收口，而不是把手写拷贝散到 Service 或 Controller

### 2.4 工具类使用

- 允许使用 Hutool，但应优先通过 `han-common-core` 封装后的工具类使用
- 不要把第三方工具 API 直接散在业务层

### 2.5 HTTP 方法与接口风格

- 管理端接口维持当前项目的 `GET / POST` 风格
- 不为了追求“更 RESTful”破坏现有接口兼容
- 新增接口时优先遵循当前项目的 `/list / add / edit / remove / export / import` 风格

## 4. 模块职责

### 4.1 核心模块

- `han-gateway`：统一网关与外部入口
- `han-auth`：认证、登录、验证码、鉴权
- `han-system`：系统管理、运行时能力、通知、监控

### 4.2 增量模块

## 5. A/I/B 控制器分层

本节是对 `AIB架构完整实施指南` 的正式吸收版。

### 5.1 当前正式定义

| 层级 | 职责 | 强制要求 |
| --- | --- | --- |
| `B` 层 | 下沉通用业务流转 | 不标 `@RestController` |
| `A` 层 | 管理端接口 | `@AdminAuth` + 权限控制 |
| `I` 层 | 内部服务调用接口 | `@InnerAuth` |

### 5.2 当前仓库真实情况

- `han-system` 已形成 `base / admin / inner` 三层结构
- 不是所有模块都已经完全完成 A/I/B 改造
- 新模块新增、老模块大改时，应优先沿用这套分层

### 5.3 新模块最小模板

- `B<Module>Controller`
  - 持有 `baseService`
  - 不暴露 HTTP 注解
  - 承载复用的业务流转方法
- `A<Module>Controller`
  - 面向前端 UI
  - 显式写权限注解
  - 操作类接口应保留操作日志与重复提交保护
- `I<Module>Controller`
  - 面向内部微服务
  - 走内部鉴权
  - 供 `@HttpExchange` 客户端调用

### 5.4 必须遵守的规则

- `B` 层禁止标注 `@RestController`
- `A` 层公开方法必须显式做权限控制
- `I` 层公开方法必须显式做内部鉴权
- `A` / `I` 层控制器应使用唯一 Bean 名称，避免冲突
- 兼容现有路由优先于“强行统一前缀”

当前参考实现：

- [BSysUserController.java](../han-modules/han-system/src/main/java/com/han/system/controller/base/BSysUserController.java)
- [ASysUserController.java](../han-modules/han-system/src/main/java/com/han/system/controller/admin/ASysUserController.java)
- [ISysUserController.java](../han-modules/han-system/src/main/java/com/han/system/controller/inner/ISysUserController.java)

## 6. 包结构与对象分层

### 6.1 推荐包结构

```text
com.han.<module>
├── controller
│   ├── admin
│   ├── inner
│   └── base
├── domain
│   ├── po
│   ├── dto
│   ├── query
│   └── vo
├── service
├── mapper
├── converter
└── <Module>Application.java
```

### 6.2 PO / DTO / Query / VO 口径

- `PO`：数据库实体
- `DTO`：写入、修改、内部流转对象
- `Query`：查询参数对象
- `VO`：页面或对外展示对象

### 6.3 当前正式要求

- 不允许在 `Query` 中用不同类型覆盖 `PO` 的同名字段
- 敏感字段必须在 `DTO / Query / VO` 层做隐藏或脱敏
- 新增复杂对象转换优先通过 `converter` 收口
- 新增分页和列表输出应优先返回 `VO`，不要把底层 `PO` 直接暴露到页面

## 7. API 与安全约束

### 7.1 通用接口原则

- 不改变已有业务语义时，不随意变更响应结构
- 页面级可见不等于功能级可用，必须同时关注接口错误与页面错误
- 对运行时能力、菜单降级和路由守卫相关接口保持一致口径

### 7.2 权限与豁免

- 管理端接口使用 `@PreAuthorize`
- 内部接口使用 `@InnerAuth`
- 公开端点必须显式说明豁免原因，不能默认裸露

### 7.3 跨模块调用

- 优先通过 `han-api` 中的 `@HttpExchange` 客户端调用
- 不要在 Service 层直接随意跨模块注入另一个业务 Service，避免耦合失控

## 8. 开放平台对接与 OAuth2 / SSO

本节吸收 `项目对接文档.md` 的有效内容，并按当前实现修正为正式口径。

### 8.1 对接前准备

第三方接入前应明确：

- `client_id`
- `client_secret`
- `redirect_uri`
- `scope`
- 回调域名与环境归属

### 8.2 当前支持的授权模式

- 授权码模式
- 授权码 + PKCE
- Client Credentials
- SSO 单点登录

### 8.3 当前正式端点

| 能力 | 正式端点 | 兼容端点 |
| --- | --- | --- |
| OAuth2 授权 | `/oauth2/authorize` | `/open/oauth2/authorize` |
| OAuth2 Token | `/oauth2/token` | `/open/oauth2/token` |
| OAuth2 UserInfo | `/oauth2/userinfo` | `/open/oauth2/userinfo` |
| SSO 登录 | `/sso/login` | `/open/sso/login` |
| SSO 校验 | `/sso/validate` | `/open/sso/validate` |
| SSO 登出 | `/sso/logout` | `/open/sso/logout` |

### 8.4 管理台应用管理入口

- 列表：`/open/app/list`
- 新增：`POST /open/app`
- 编辑：`POST /open/app/edit`
- 启停：`POST /open/app/changeStatus`
- 重置密钥：`POST /open/app/resetSecret/{appId}`

### 8.5 对接安全要求

- 浏览器或移动端场景优先使用 PKCE
- 前端不得暴露 `client_secret`
- 必须校验 `state`
- 所有接入说明都应默认 HTTPS
- 文档示例和实际代码示例优先使用当前项目支持的请求风格

## 9. 编码规范

### 9.1 通用要求

- 保留现有能力，不得偷简化
- 公共类、接口、复杂逻辑要有清晰注释
- 保持错误处理、边界处理和恢复逻辑明确
- 避免魔法值，优先抽常量

### 9.2 文档同步要求

- 代码变更与文档变更尽量同一轮完成
- 涉及结构变化时必须同步更新规则与索引
- 需要说明未验证部分，禁止默认“应该可用”

## 10. 测试与提测要求

### 10.1 最低测试要求

- 后端 Java 变更至少执行受影响模块测试
- 前端变更至少执行 `pnpm build`
- 核心页面与关键流程改动必须做 Playwright 或人工回归
- 部署、联调、运行时能力变更必须补冒烟验证

### 10.2 页面级健康回归要求

- 捕获 `HTTP 4xx/5xx`
- 捕获业务 `code != 200`
- 捕获 `requestfailed`
- 捕获 `pageerror`
- 捕获 `console error`

正式测试口径以 [测试与验收手册](04-测试与验收手册.md) 为准。
