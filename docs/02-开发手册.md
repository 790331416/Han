# 开发手册

## 1. 基础环境

- JDK 21
- Maven 3.9+
- Node.js 18+
- Docker 26+
- Docker Compose 2.x

## 2. 推荐命令

```powershell
mvn -gs settings.workspace.xml -DskipTests compile
```

```powershell
cd han-ui
pnpm install
pnpm build
```

## 3. 本地开发流程

1. 启动基础依赖
2. 导入项目到 IDE
3. 初始化数据库与 Nacos
4. 按依赖顺序启动后端服务
5. 启动前端
6. 做最小联调验证

## 4. 模块职责

### 4.1 核心模块

- `han-gateway`：统一网关与外部入口
- `han-auth`：认证、登录、验证码、鉴权
- `han-system`：系统管理、运行时能力、通知、监控
- `han-job`：任务调度与 JobFlow 监控

### 4.2 增量模块

- `han-tenant`：多租户能力
- `han-workflow`：流程定义、实例、待办、已办
- `han-open`：开放平台与 OAuth2 / SSO
- `han-file`：文件与 OSS
- `han-ai`：模型、知识库、Prompt、MCP、应用、对话
- `han-gen`：代码生成

## 5. 编码规范

### 5.1 通用要求

- 保留现有能力，不得偷简化
- 公共类、接口、复杂逻辑要有清晰注释
- 保持错误处理、边界处理和恢复逻辑明确
- 避免魔法值，优先抽常量

### 5.2 提交要求

- 代码变更与文档变更尽量同一轮完成
- 涉及结构变化时必须同步更新规则与索引
- 需要说明未验证部分，禁止默认“应该可用”

## 6. 接口边界规范

### 6.1 原则

- 不改变已有业务语义时，不随意变更响应结构
- 页面级可见不等于功能级可用，必须同时关注接口错误与页面错误
- 对运行时能力、路由守卫和菜单降级相关接口保持一致口径

### 6.2 测试要求

- 页面回归要同时捕获 HTTP `4xx/5xx`
- 页面回归要捕获业务 `code != 200`
- 页面回归要捕获 `pageerror` 与 `console error`
- 新增页面时应考虑是否纳入页面级健康回归

## 7. 文档与结构协同规则

- 文档、SQL、部署结构变更必须同步更新正式文档
- 前端变更不得依赖仓库中的历史 `dist`
- 本地验证优先使用正式 compose 和正式测试脚本
- 正式入口只认 `README.md`、`docs/`、`sql/`、`deploy/`

## 8. 开发者自检清单

- 是否保持原有能力不缩水
- 是否同步更新了 README 或正式手册
- 是否同步更新了 SQL / deploy 入口说明
- 是否补了最小验证结果
- 是否明确了边界项和未验证项
