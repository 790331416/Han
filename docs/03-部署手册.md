## 1. 部署方案选择

### 1.1 三档部署对比

| 档位 | 适用场景 | 建议资源 | 默认能力 | 正式部署入口 |
| --- | --- | --- | --- | --- |
| `small` | 本地开发、演示、核心链路验证 | 2 核 4GB | 核心后台、通知、任务调度、监控 | `deploy/small/docker-compose.yml` |
| `medium` | 团队联调、标准测试环境 | 4 核 8GB | `small` + 租户、工作流、开放平台、文件服务 | `deploy/medium/docker-compose.yml` |
| `full` | 完整业务联调、AI 联调、发布预演 | 8 核 16GB+ | `medium` + AI 与代码生成 | `deploy/full/docker-compose.yml` |

### 1.2 正式入口

- `small`：`deploy/small/docker-compose.yml`
- `medium`：`deploy/medium/docker-compose.yml`
- `full`：`deploy/full/docker-compose.yml`

禁止继续把根目录历史 `docker-compose*.yml` 作为长期正式部署入口。

## 2. 通用部署前检查

### 2.1 必查文件

- 对应 tier 的 `deploy/<tier>/docker-compose.yml`
- 对应 tier 的 `.env`
- 对应 tier 的 PostgreSQL 初始化 SQL
- 对应 tier 的 Nacos 导入 SQL

### 2.2 必查变量

- `HAN_DEPLOY_TIER`
- `HAN_INNER_AUTH_SECRET`
- 数据库连接信息
- Redis 连接信息
- Nacos 连接信息
- AI Provider 密钥
- 对象存储和消息队列连接信息

### 2.3 初始化规则

- PostgreSQL 初始化只认 `sql/tiers/<tier>/<tier>-init.sql`
- Nacos 导入只认 `sql/tiers/<tier>/<tier>-nacos-derby-import.sql`
- 增量升级只认 `sql/upgrades/postgres/`

## 6. 本地开发环境部署

本节吸收了历史部署文档中的本地开发内容，但路径和初始化入口改为当前正式结构。

### 6.1 仅启动中间件

本地联调时，只启动中间件和必要依赖，不建议再维护一套独立旧脚本。

### 6.2 本地初始化顺序

1. 导入对应 tier 的 PostgreSQL SQL
2. 导入对应 tier 的 Nacos SQL 或按正式模板创建配置
3. 启动网关、认证、系统及所需业务模块
4. 启动前端

### 6.3 Nacos 说明

- JobFlow 相关配置已并入各 tier Nacos 导入 SQL
- 本地如果不直接导 SQL，应至少补齐正式手册中要求的配置项

## 7. Kubernetes / 生产预演说明

本节保留历史部署文档中的有效内容，但当前仓库正式交付以三档 Docker Compose 为主。

### 7.1 当前口径

- `small / medium / full` 的正式交付入口是 `deploy/`
- Kubernetes 方案可用于生产预演或后续演进
- 生产环境应优先考虑：
  - PostgreSQL 高可用
  - Redis 高可用
  - Nacos 集群
  - 可观测性外挂

### 7.2 生产关注项

- 资源限制与探针
- 滚动更新策略
- 密钥管理
- 监控与告警
- 回滚路径

## 8. 配置与密钥管理

### 8.1 原则

- secrets 不进 Git
- 只通过受控环境变量文件或 secrets 管理位置注入
- 同一 tier 的服务共享同一套必要密钥来源

### 8.2 重点配置

- `HAN_DEPLOY_TIER`
- `HAN_INNER_AUTH_SECRET`
- 数据库连接
- Redis 连接
- Nacos 连接
- RustFS / RabbitMQ 连接
- AI Provider 密钥

## 9. 备份、回滚与升级

### 9.1 PostgreSQL

- 发布前建议做逻辑备份
- 发布后如有结构变更，记录已执行的升级脚本

### 9.2 Nacos

- 导入前备份 Derby 数据目录或当前配置
- 变更后记录导入的脚本版本

### 9.3 回滚

1. 确认要回滚的提交
2. 在正式仓库切到对应提交
3. 重新构建并拉起对应 tier
4. 重新验证运行时能力和主链路

## 10. 故障排查

本节吸收了历史部署文档中的常见排障内容，并按当前正式结构简化。

### 10.1 推荐排障顺序

1. PostgreSQL
2. Redis
3. Nacos
4. Gateway
5. 核心业务服务
6. UI
7. 页面级健康回归

### 10.2 常见问题

- 服务启动失败
  - 先看容器日志
  - 再看环境变量与连接信息
- Nacos 注册或配置未生效
  - 先确认 Nacos 是否活着
  - 再确认配置是否真的导入到当前 tier
- 数据库连接失败
  - 检查数据库实例、库名、用户、密码
- 页面能开但里面报 404 / 500
  - 先跑页面级健康回归
  - 再查服务日志与运行时能力

## 11. 禁止项

- 不再使用根目录旧 compose 作为长期正式入口
- 不得手工上传 `jar`、`dist`
- 不得依赖历史构建产物做发布
- 不得把 secrets 写入 Git
- 不得在 95 上继续沿用历史临时发布目录
