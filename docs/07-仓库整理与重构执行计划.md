# 仓库整理与重构执行计划

## 1. 计划定位

本文档是 Han 仓库后续整理的唯一主计划。

后续所有整理动作都以本计划为准，目标不是继续把仓库拆成大量碎文档，而是参考若依文档的组织方式，收敛为：

- 一个大 README
- 少量正式大手册
- 一份总规则文档
- 每档一个大 SQL
- 一套正式部署入口

## 2. 参考口径

本计划参考了若依的文档与仓库组织方式：

- [RuoYi 文档](https://doc.ruoyi.vip/ruoyi/)
- [RuoYi-Cloud 文档](https://doc.ruoyi.vip/ruoyi-cloud/)
- [RuoYi-Cloud 仓库](https://gitee.com/y_project/RuoYi-Cloud)

参考后的结论：

- README 应承担项目介绍、能力说明、快速开始和文档导航
- 正式文档应按大手册组织
- 微服务专题应收敛进少量大文档
- SQL 入口应简洁直接
- 历史资料应归档，不再占正式入口

## 4. 实施顺序

### 第一阶段：恢复正式入口

- 恢复 `README.md` 为大文档
- 建立 `docs/` 顶层大手册结构
- 停止新增碎片化正式文档

### 第二阶段：合并正式文档

- 将当前碎文档合并进 7 份正式大文档
- 将旧碎文档迁入 `docs/archive/`

### 第三阶段：重构 SQL

- 将现有分模块 SQL 合并为：
  - `small-init.sql`
  - `medium-init.sql`
  - `full-init.sql`
- 保留每档一个 Nacos 导入脚本
- 保留升级脚本目录
- 历史 SQL 统一归档

### 第四阶段：收敛部署入口

- 统一三档部署说明到 `deploy/` 和部署手册
- 根目录旧 compose 逐步退役

### 第五阶段：收敛规则

- 所有治理规则收敛为一份总规则文档
- 检查脚本同步改成校验最终目标结构

### 第六阶段：95 重新验证

- 按新结构部署
- 做页面级健康回归
- 做主链路回归
- 做 Full AI 专项回归

## 5. 验收标准

- `README.md` 恢复为大文档
- `docs/` 正式文档收敛为少量大手册
- `06-牛马协作总规则.md` 成为唯一正式规则文档
- `sql/tiers/<tier>/` 每档只保留一个大初始化 SQL 和一个 Nacos 导入 SQL
- `deploy/` 成为唯一正式部署入口
- 95 目录结构收敛到目标态
- 新 SQL 在干净环境中可直接导入
- 三档核心功能验证通过

本节记录本计划的执行现状，避免计划文档与仓库实际结构脱节。仅陈述现状，不代表已就残留项做出处置决定。
