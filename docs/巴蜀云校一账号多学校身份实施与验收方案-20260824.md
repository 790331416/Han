# 巴蜀云校一账号多学校身份实施与验收方案（2026-08-24）

## 1. 业务场景

同一个自然人使用同一个 `sys_user` 登录账号，可关联多条 `edu_person` 身份（A 学校管理员、B 学校教师等）。登录后识别全部有效身份，多身份时显式选择，菜单、接口权限、数据范围和课堂凭证均跟随当前身份隔离。

## 2. 当前问题（已审计确认）

- `LoginUser` 无身份字段；登录响应无 `requireIdentity`。
- 菜单/权限按 `userId` 全角色并集（`SysMenuServiceImpl.selectMenuIdsByUserId`、`SysUserMapper.xml` 三条 SQL）。
- `EducationDataScopeService.current()` 按账号合并多校。
- 绑定/解绑/角色清理/停用全账号级，波及同账号其他身份。
- 课堂 Active Key 按 `hanUserId`，4 处「未传 identityId 默认取第一条」，目录接口只校验 schoolId。

## 3. 数据模型

`sys_user`（账号） ← `edu_person.user_id`（身份），每条 `edu_person` 只属一个 `school_id`，`identityId = edu_person.id`。学校名称实时取 `edu_school`；姓名/手机号沿用 `EducationAccountIdentityService` 同步。本期**不新增** `edu_person_role`。

## 4. 身份选择流程

- 0 个有效身份：系统账号原流程。
- 1 个：自动选择、签发含身份会话。
- ≥2 个：返回 `requireIdentity=true + identityTicket（Redis 一次性，5 分钟）+ identities[]`；`POST /auth/identity/select` 消费票据后签发正式 token。

## 5. 权限计算方式

- 系统账号：原 `sys_user_role` 逻辑。
- `SCHOOL_ADMIN`（personType=TEACHER, dutyCode=SCHOOL_ADMIN）：账号非 teacher/student 管理角色并集，数据范围收敛 `school_id`。
- `TEACHER/STUDENT`：不继承账号管理角色，管理端 `managementAvailable=false`，课堂走独立 roleType 链路。

## 6. 数据范围规则

`LoginUser.identityScoped=true` 时，有效学校仅 `LoginUser.schoolId`；前端 schoolId 只能筛选不能扩大；非身份系统账号保留 `edu_user_scope`/租户管理员/超管逻辑。

## 7. 绑定和解绑规则

- 新增第二身份：关联已有账号不建新 `sys_user`、不重置密码、不清角色，只新增 `edu_person` 绑定；同校同有效身份不得重复；禁止跨租户。
- 解绑：只置当前 `edu_person.user_id=null`，不删人员/账号，不影响其他身份；最后一个教育入口创建的客户端账号才停用，独立系统账号不停用。
- 普通教师/学生身份的新增/编辑不清空账号为其他学校管理员保留的角色。

## 8. 密码影响范围

密码属 `sys_user`；重置密码影响账号全部身份并明确提示；未绑定人员禁用重置。

## 9. 课堂凭证规则

Token Claims 含 `hanUserId/identityId/schoolId/personType/roleType`；Active Key 按 `userId+identityId`；多身份未传 identityId 报错；切换/解绑后旧身份课堂 token 失效；登出撤销当前会话关联课堂凭证；目录接口按 token 中身份与学校做服务端校验。

## 10. 数字校园规则

多身份显式选择 `identityId`；每个外部身份同步为独立 `edu_person`；用 `external_identity_id` 幂等；用稳定外部标识/经校验手机号匹配账号，不按姓名。

## 11. 接口清单

- `POST /auth/identity/select`（消费 identityTicket + identityId）
- `GET /auth/identities`（当前账号有效身份 + 当前身份）
- `POST /auth/identity/switch`（identityId，换发 token + 作废旧会话/旧课堂凭证）
- 登录响应扩展：`requireIdentity/identityTicket/identities/currentIdentity`

## 12. SQL 执行顺序

`sql/han/mysql/20260824_multi_school_identity.sql`：只补必要的身份查询组合索引；修复必要的教师/学生权限档案；不删除历史数据、不用姓名做关联键、不用固定自增 ID 假设角色/菜单。执行前检查 → 迁移 → 执行后核验 → 回滚说明四段式。

## 13. 测试清单

见任务书 20 节：后端核心 20 场景、账号绑定 11 场景、名称同步 5 场景、菜单前端 10 场景。

## 14. 兼容说明

无身份系统账号、单身份账号、旧登录响应字段、单身份课堂凭证、数字校园单身份、超管、区域/学校数据范围授权、姓名手机号同步全部保持兼容。

## 15. 风险和回滚

- 越权/跨校读：靠服务层身份归属 + 数据范围收敛双重校验。
- 会话兼容：LoginUser 新增字段默认 null，旧 token 反序列化兼容。
- 回滚：按功能分提交，逐提交可回退；SQL 全部幂等可重复执行。

## 16. 本期不支持

不同学校配置两套完全不同的自定义管理员角色（即 A 校管理员角色 X、C 校管理员角色 Y）；不新增身份角色关联表。
