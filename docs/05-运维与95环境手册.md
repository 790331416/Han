本手册吸收并收口了归档区中的以下关键材料：

## 1. 95 正式目录

- `/opt/han/repo/Han`
- `/opt/han/deploy/small`
- `/opt/han/deploy/medium`
- `/opt/han/deploy/full`
- `/opt/han/backups/pre-rebuild/<timestamp>`
- `/opt/han/logs`
- `/opt/han/archive`

## 2. 95 固定发布链路

1. 本地代码进入 `master`
2. 95 在 `/opt/han/repo/Han` 执行 `git pull --ff-only origin master`
3. 在 95 本机完成构建
4. 从 `/opt/han/deploy/{small,medium,full}` 执行 compose
5. 跑固定验证清单
6. 记录提交、构建、部署和验证结果

## 3. 95 禁止项

- 继续使用 `/opt/han/source/Han-*` 目录发布
- 继续用 `/opt/han/docker` 作为正式入口
- 手工上传 `jar` 或 `dist`
- 保留无说明的 canary/live 混合目录
- 发布后不留验证记录

## 4. Nacos 配置说明

### 4.1 正式位置

- `small`：`sql/tiers/small/small-nacos-derby-import.sql`
- `medium`：`sql/tiers/medium/medium-nacos-derby-import.sql`
- `full`：`sql/tiers/full/full-nacos-derby-import.sql`

### 4.2 原则

- Nacos 导入脚本与 PostgreSQL 初始化脚本分开管理
- tier 专用配置不得散落在 `sql/` 根目录
- 95 导入前先备份原始 Derby 数据目录
- 运行时临时变更要能回溯到导入脚本或明确的运维记录

## 5. PostgreSQL 初始化与升级

### 5.1 通用顺序

1. 初始化 tier SQL
2. 执行 tier 对应 Nacos 导入
3. 执行必要的升级脚本
4. 拉起服务后验证运行时能力

### 5.2 tier 口径

- `small`：system、job
- `medium`：在 `small` 基础上增加 tenant、workflow、open、file
- `full`：在 `medium` 基础上增加 ai、aivideo、gen

### 5.3 升级脚本原则

- 只认 `sql/upgrades/postgres/`
- 执行过的升级脚本必须记录
- 影响历史数据可见性、租户隔离、索引、兼容路径时，升级后必须补回归

### 7.4 镜像仓库发布

95 本机重建服务镜像后，若该镜像需要作为正式发布产物复用，必须推送到 `registry.cn-hangzhou.aliyuncs.com/xzy0112` 并验证可拉取。

正式脚本：

```bash
HAN_IMAGE_PUBLISH_CONFIRM=1 deploy/scripts/publish-service-images-95.sh --images open,file,ai,aivideo --verify-pull
```

不可变批次 tag：

```bash
HAN_IMAGE_PUBLISH_CONFIRM=1 deploy/scripts/publish-service-images-95.sh --images open,file,ai,aivideo --tag <release-tag> --source-tag latest --retag-from-source --verify-pull
```

执行边界：

- 只发布本机已有镜像，不在脚本内构建镜像
- 可把已验证源 tag 复制成不可变发布 tag
- 不读取或输出镜像仓库凭据
- 不重启容器
- 不删除镜像、volume、运行库或对象存储数据
- 执行后记录来源提交、镜像名、推送结果、拉取验证结果、digest pin 和残留风险

发布批次完成后，必须把已验证 digest pin 固化为 `deploy/release-manifests/<release-tag>.env`：

```bash
deploy/scripts/generate-image-release-manifest-95.sh \
  --tag <release-tag> \
  --source-commit <commit> \
  --services gateway,auth,system,job,tenant,workflow,open,file,ai,aivideo,gen,ui \
  --output deploy/release-manifests/<release-tag>.env
```

发布清单只记录镜像仓库地址、来源提交、服务列表和 `repo@sha256:<digest>`，不得写入任何服务器密码、镜像仓库凭据、数据库密码或令牌。

按 digest 回滚时，先把 `.env` 中的对应镜像变量改成脚本输出的 `HAN_<SERVICE>_IMAGE=<repo>@sha256:<digest>`，再在 `/opt/han/deploy/<tier>` 执行 `docker compose pull <service>` 与 `docker compose up -d --no-deps --force-recreate <service>`。回滚后必须补跑专项探针和 `verify-95.sh`。

正式 digest 部署演练脚本：

```bash
deploy/scripts/rehearse-image-digest-deploy-95.sh --tag <release-tag> --target all --apply
```

也可使用已固化的发布清单：

```bash
deploy/scripts/rehearse-image-digest-deploy-95.sh --manifest deploy/release-manifests/<release-tag>.env --target all --apply
```

该脚本只用临时环境变量把服务镜像解析为 digest pin，不修改 `.env`，不清库，不删除 volume。执行后必须补跑 `verify-95.sh` 和对应专项探针。

全应用服务演练可显式指定服务列表：

```bash
deploy/scripts/rehearse-image-digest-deploy-95.sh --tag <release-tag> --target all --services gateway,auth,system,job,tenant,workflow,open,file,ai,aivideo,gen,ui --apply
```

使用发布清单覆盖全应用服务时：

```bash
deploy/scripts/rehearse-image-digest-deploy-95.sh --manifest deploy/release-manifests/<release-tag>.env --target all --services gateway,auth,system,job,tenant,workflow,open,file,ai,aivideo,gen,ui --apply
```

## 10. 当前高频问题口径

- 服务刚重启后短窗口抖动
  - 先等健康检查翻绿
  - 再做页面回归
- 页面壳子打开但内部报错
  - 以页面级健康回归为准，不以“能进页面”判绿
- Token 首轮失效
  - 先确认鉴权链路与服务稳定性
  - 再判断是否属于短时会话抖动
