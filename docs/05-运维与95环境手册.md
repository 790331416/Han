# 运维与95环境手册

本手册吸收并收口了归档区中的以下关键材料：

- `docs/archive/2026/分析/server-95-deploy-flow.md`
- `docs/archive/2026/分析/environment-recovery-checklist-20260402.md`
- `docs/archive/2026/分析/项目部署文档.md`

95 相关运维与发布口径以本手册为准。

## 1. 95 正式目录

- `/opt/han/repo/Han`
- `/opt/han/deploy/small`
- `/opt/han/deploy/medium`
- `/opt/han/deploy/full`
- `/opt/han/backups/pre-rebuild/<timestamp>`
- `/opt/han/logs`
- `/opt/han/archive`

## 2. 95 固定发布链路

1. 本地代码进入 `master`
2. 95 在 `/opt/han/repo/Han` 执行 `git pull --ff-only origin master`
3. 在 95 本机完成构建
4. 从 `/opt/han/deploy/{small,medium,full}` 执行 compose
5. 跑固定验证清单
6. 记录提交、构建、部署和验证结果

## 3. 95 禁止项

- 继续使用 `/opt/han/source/Han-*` 目录发布
- 继续用 `/opt/han/docker` 作为正式入口
- 手工上传 `jar` 或 `dist`
- 保留无说明的 canary/live 混合目录
- 发布后不留验证记录

## 4. Nacos 配置说明

### 4.1 正式位置

- `small`：`sql/tiers/small/small-nacos-derby-import.sql`
- `medium`：`sql/tiers/medium/medium-nacos-derby-import.sql`
- `full`：`sql/tiers/full/full-nacos-derby-import.sql`

### 4.2 原则

- Nacos 导入脚本与 PostgreSQL 初始化脚本分开管理
- tier 专用配置不得散落在 `sql/` 根目录
- 95 导入前先备份原始 Derby 数据目录
- 运行时临时变更要能回溯到导入脚本或明确的运维记录

## 5. PostgreSQL 初始化与升级

### 5.1 通用顺序

1. 初始化 tier SQL
2. 执行 tier 对应 Nacos 导入
3. 执行必要的升级脚本
4. 拉起服务后验证运行时能力

### 5.2 tier 口径

- `small`：system、job
- `medium`：在 `small` 基础上增加 tenant、workflow、open、file
- `full`：在 `medium` 基础上增加 ai、gen

### 5.3 升级脚本原则

- 只认 `sql/upgrades/postgres/`
- 执行过的升级脚本必须记录
- 影响历史数据可见性、租户隔离、索引、兼容路径时，升级后必须补回归

## 7. 标准运维动作

### 7.1 健康检查

- 检查容器是否存活
- 检查 `/system/runtime/capabilities`
- 检查登录链路
- 检查页面级健康回归

### 7.2 日志排查

优先顺序：

1. gateway
2. auth
3. 对应业务服务
4. ui 访问日志

### 7.3 数据与配置备份

- PostgreSQL：发布前做逻辑备份
- Nacos：导入前备份 Derby 数据目录
- `.env`：变更后留存版本化记录，但 secrets 不进 Git

## 8. 环境清理手册

### 8.1 仓库清理

- 清理构建产物
- 清理缓存目录
- 清理临时验证文件
- 清理无用分支

### 8.2 95 清理

1. 备份必要 secrets
2. 停止并删除 Han 相关容器
3. 清理旧镜像、旧网络、旧 volume
4. 清理旧源码目录和旧部署目录
5. 按新目录重建

## 9. 常见排障顺序

1. PostgreSQL
2. Redis
3. Nacos
4. Gateway
5. 核心业务服务
6. UI
7. 页面级健康回归

## 10. 当前高频问题口径

- 服务刚重启后短窗口抖动
  - 先等健康检查翻绿
  - 再做页面回归
- 页面壳子打开但内部报错
  - 以页面级健康回归为准，不以“能进页面”判绿
- Token 首轮失效
  - 先确认鉴权链路与服务稳定性
  - 再判断是否属于短时会话抖动

## 11. 运维留痕要求

- 发布前记录来源提交
- 发布后记录运行态与验证结果
- 出现问题记录故障时间、影响范围、恢复动作
- 所有一次性故障文档进入 `docs/archive/`
