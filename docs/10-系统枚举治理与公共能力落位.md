# 系统枚举治理与公共能力落位

## 1. 目标

本说明用于统一 Han 仓库内“字典、系统配置、Prompt 模板、模型管理”四类公共能力的落位规则，避免：

- 同一组枚举在前后端重复写死；
- 应该进系统中心的数据被散落在业务模块；
- 长文本 Prompt、默认配置、模型元数据和枚举选项混在一起维护；
- AIVideo、AI 能力和其他业务模块各自长出一套平行实现。

## 2. 四类能力怎么分

| 类型 | 适合承载什么 | 典型例子 | 不适合放什么 |
| --- | --- | --- | --- |
| 字典 | 可枚举、可下拉选择、可按标签展示、会被多个页面复用的数据 | 状态、策略、风格、分类、类型、权限级别 | 长文本正文、密钥、单个默认值 |
| 系统配置 | 单值运行参数、默认开关、候选数量、阈值、地址 | 默认画幅、默认候选数、超时时间、是否开启某能力 | 多个可选标签列表 |
| Prompt 模板 | 长文本提示词、变量化模板、系统提示词 | 文本润色模板、剧本模板、视频提示词模板 | “正常/停用”这类短枚举 |
| 模型管理 | 模型元数据、供应商、凭证来源、能力说明 | LLM/图片/视频/TTS 模型接入信息 | 页面状态、业务策略枚举 |

## 4. 还建议继续字典化的数据

下面这些数据已经具备“多页面复用、需要中文标签、未来可能运营调整”的特征，适合后续继续沉淀到字典中心：

### 4.1 通用 AI / 工作流侧

- `workflow_process_category`
  - 流程分类，如 `OA / HR / FINANCE / PROJECT / OTHER`

- `ai_conversation_source_type`
  - 对话来源类型，如“工作流 / 智能体 / 直接模型”

  - 角色声线类型，如旁白、主角、配角、童声、青年女声、中年男声

  - 说话风格，如温柔、理性、活泼、紧张、低声播报

  - 背景音乐风格，如温暖日常、悬疑紧张、治愈、史诗、轻喜剧

  - 音效类别，如脚步、雷声、翻页、门响、掌声、环境底噪

  - 转场类型，如硬切、淡入淡出、叠化、闪白、黑场

- `aivideo_clip_merge_mode`
  - 成片合成策略，如直接拼接、插转场、统一混音后拼接

## 5. 哪些不要放字典

下面这些内容不应该塞进字典：

- 默认模型 ID、默认供应商、默认候选数。
  - 这类属于系统配置。
- 火山 AK/SK、Token、VOD Space、第三方密钥。
  - 这类属于凭证或系统配置。
- 文本润色 Prompt、剧本 Prompt、视频 Prompt 正文。
  - 这类属于 Prompt 模板。
- 模型 baseUrl、modelCode、凭证来源、能力说明。
  - 这类属于模型管理。
- 媒体访问地址、文件路径、回源域名。
  - 这类属于配置或文件服务数据。

## 6. 页面维护口径

如果某个页面只是需要“下拉可选项 + 标签展示”，优先按下面顺序处理：

1. 先查系统是否已有对应字典。
2. 如果已有，直接复用公共字典加载器。
3. 如果没有，再评估应进字典、配置、Prompt 模板还是模型管理。
4. 如果因为兼容阶段必须保留本地 fallback，注释里必须写清楚 fallback 的目的和后续移除条件。

## 7. 管理端怎么维护实际值

字典类型页只维护“类型头”，真正的值列表要去字典数据页维护：

1. 进入 `系统管理 -> 字典管理`
2. 找到目标字典类型
3. 点击行内 `数据项`
4. 在字典数据页维护 `字典标签 / 字典键值 / 排序 / 状态 / 样式`

如果后续某项数据决定改为系统配置或 Prompt 模板，就不要继续往字典里塞。

## 8. 当前推荐执行策略

当前仓库建议按下面优先级持续推进：

1. 所有“正常 / 停用”统一吃 `sys_normal_disable`
2. 所有 AI / AIVideo 状态、风格、策略页面统一改用公共字典加载器
3. 再把工作流分类、流程实例状态、AIVideo 语音/BGM/音效相关枚举收口到字典
4. 最后清理页面里仅剩的 fallback 常量

## 9. 与公共模块的关系

- 优先复用 Han 系统现有能力，不另起一套平行枚举系统。
- 修改公共模块时，只沉淀“其他模块也能调用”的能力。
- AIVideo 私有编排规则、模型限制、剧本逻辑不要直接硬编码进字典公共层。
- 公共层负责：
  - 字典定义
  - 字典加载
  - fallback 兼容
  - 标签展示工具
  - 系统管理维护入口
