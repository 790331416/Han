## 1. 设计依据

本接口草案基于：
- `D:\code\AIVideo\docs\设计规划\Han模块边界设计.md`
- `D:\code\AIVideo\docs\设计规划\AI短剧页面设计规划.md`
- `D:\code\AIVideo\docs\设计规划\AI短剧数据库表设计.md`
- `D:\code\Han\docs\02-开发手册.md`
- `D:\code\Han\.codex\rules\20-engineering-baseline.md`
- Han 当前前端 API 风格：`GET /list`、`POST /add`、`POST /edit`、`POST /remove`

Han 技术约束：
- 管理端接口维持当前 `GET / POST` 风格，不强行改成 RESTful。
- 新模块遵守 A/I/B 分层：`controller/admin`、`controller/base`、必要时 `controller/inner`。
- A 层接口必须显式权限控制。
- 内部服务调用优先 `@HttpExchange`，禁止新增 Feign。
- JSON 使用 Jackson，转换使用 MapStruct 或 Converter。
- API Key 不返回前端。

## 2. 接口分组

第一版建议后端接口分为两类：

| 分组 | 前缀 | 使用者 | 说明 |
| --- | --- | --- | --- |
| 创作端接口 | `/aivideo/studio/*` | 普通用户/创作者 | `/studio` 页面调用 |
| 管理端接口 | `/aivideo/admin/*` | 管理员/运营 | Han 管理端 AI 短剧页面调用 |

说明：
- 是否最终挂 `/aivideo`、`/ai/video` 或 `/ai/aivideo`，以 Han 网关和菜单规范确认后为准。
- 本草案先用 `/aivideo`，避免和 `han-ai` 现有 `/ai/*` 混淆。
- 如果 Han 既有权限命名要求统一为 `ai:aivideo:*`，权限码按该前缀设计。

## 3. 创作端接口

### 3.1 项目列表

```text
GET /aivideo/studio/project/list
```

Query：
- `projectName`
- `projectStatus`
- `currentStage`
- `pageNum`
- `pageSize`

权限：
- 普通用户只能看自己的项目。
- 管理员可通过管理端看全部，不建议创作端默认看全部。

返回：
- `projectId`
- `projectName`
- `topicType`
- `targetPlatform`
- `currentStage`
- `projectStatus`
- `actualCost`
- `updateTime`

### 3.2 项目详情

```text
GET /aivideo/studio/project/{projectId}
```

返回：
- 项目主信息。
- 项目设置快照。
- 当前阶段。
- 各步骤确认状态。
- 最近任务状态。

### 3.3 新建项目

```text
POST /aivideo/studio/project
```

Body：
- `projectName`
- `topicType`
- `targetPlatform`
- `defaultRatio`
- `defaultStyle`
- `defaultShotDuration`
- `candidateImageCount`
- `previewMode`
- `sourceType`
- `rawText`
- `fileId`

处理：
- 创建 `ai_video_project`。
- 创建 `ai_video_project_setting` 快照。
- 如果有原文，创建 `ai_video_source_document`。
- 初始阶段为 `DRAFT`。

### 3.4 编辑项目基础信息

```text
POST /aivideo/studio/project/edit
```

限制：
- 已进入视频生成后，部分字段只允许影响后续任务，不回改历史任务。
- 已归档项目不允许直接编辑，需先恢复。

### 3.5 上传原文

第一版复用 Han 文件服务：

```text
POST /file/upload
```

上传成功后，创作端调用：

```text
POST /aivideo/studio/document/save
```

Body：
- `projectId`
- `sourceType`
- `fileId`
- `fileName`
- `rawText`

说明：
- 粘贴文本可不走 `/file/upload`。
- TXT/Markdown 文件建议先走文件服务，再由 `han-aivideo` 读取或保存解析结果。

### 3.6 文档解析确认

生成/解析：

```text
POST /aivideo/studio/document/parse
```

确认：

```text
POST /aivideo/studio/document/confirm
```

Body：
- `projectId`
- `documentId`
- `chapterJson`
- `parsedText`

确认后：
- 项目阶段进入 `DOCUMENT_PARSED`。
- 写入 `ai_video_review_record`。

## 4. 文本生成接口

### 4.1 生成润色稿

```text
POST /aivideo/studio/generate/polish
```

Body：
- `projectId`
- `documentId`
- `promptTemplateId`
- `customPrompt`
- `candidateCount`
- `modelId`

处理：
- 校验文档解析已确认。
- 创建 `ai_video_generation_task`。
- 调用 `han-ai` 文本能力。
- 写入 `ai_video_content_version`，`contentType = POLISH`。

### 4.2 确认润色稿

```text
POST /aivideo/studio/content/confirm
```

Body：
- `projectId`
- `versionId`
- `contentType`
- `comment`

处理：
- 同类型其他版本标记非选中。
- 当前版本标记 `APPROVED`。
- 项目阶段进入 `POLISH_CONFIRMED`。
- 写入确认记录。

### 4.3 生成剧本

```text
POST /aivideo/studio/generate/script
```

Body：
- `projectId`
- `sourceVersionId`
- `episodeCount`
- `targetDuration`
- `customPrompt`
- `modelId`

生成结果：
- 写入 `ai_video_content_version`，`contentType = SCRIPT`。

### 4.4 提取人物/场景/分镜

```text
POST /aivideo/studio/generate/extract
```

Body：
- `projectId`
- `scriptVersionId`
- `extractTypes`: `CHARACTER`、`SCENE`、`SHOT`
- `customPrompt`
- `modelId`

处理：
- 先写入 `ai_video_content_version` 结构化提取结果。
- 再由 `han-aivideo` 解析并落入：
  - `ai_video_character`
  - `ai_video_scene`
  - `ai_video_shot`

### 4.5 AI 补全人物/场景

```text
POST /aivideo/studio/generate/complete-asset
```

Body：
- `projectId`
- `assetType`: `CHARACTER` / `SCENE`
- `assetId`
- `customPrompt`
- `modelId`

处理：
- 只更新指定资产的待补字段。
- 更新前后写入确认或操作记录。

## 7. 视频生成接口

### 7.1 成本预估

```text
POST /aivideo/studio/video/estimate
```

Body：
- `projectId`
- `shotIds`
- `modelId`
- `ratio`
- `resolution`
- `durationSec`
- `mode`: `TEXT_TO_VIDEO` / `IMAGE_TO_VIDEO`

返回：
- `estimatedCost`
- `currency`
- `riskWarnings`
- `canGenerate`
- `blockReason`

### 7.2 创建视频生成任务

```text
POST /aivideo/studio/video/generate
```

Body：
- `projectId`
- `shotIds`
- `modelId`
- `ratio`
- `resolution`
- `durationSec`
- `mode`
- `confirmedCost`
- `customPrompt`

处理：
- 必须先成本预估。
- 必须确认前置资产已通过。
- 创建 `ai_video_generation_task`。
- 交给 `han-job` 或模块内异步执行。
- 底层由 `han-ai` 调用火山视频 API。

### 7.3 查询视频任务

```text
GET /aivideo/studio/video/task/{taskId}
```

返回：
- `taskStatus`
- `progress`
- `providerTaskId`
- `errorMessage`
- `mediaList`

### 7.4 取消/重试视频任务

```text
POST /aivideo/studio/video/cancel/{taskId}
POST /aivideo/studio/video/retry/{taskId}
```

## 10. 内部接口建议

如后续 `han-ai`、`han-file`、`han-job` 需要跨模块内部调用，优先在 `han-api` 中定义 `@HttpExchange` 客户端。

候选：
- `AivideoInternalServiceClient`
- `AiModelInvokeClient`
- `FileServiceClient` 已有时优先复用。

禁止：
- 新增 Feign。
- 在 Service 层随意跨模块注入另一个业务 Service。
- 前端绕过 `han-aivideo` 直接调 `han-ai` 执行短剧业务流程。

## 11. 返回结构建议

沿用 Han 当前 `R<T>` 和分页结果风格。

业务错误：
- 权限不足。
- 前置步骤未确认。
- 预算不足。
- 模型未配置。
- API Key 未配置。
- 火山任务失败。
- 文件不存在或无权限。

错误信息必须可读，但不得泄露完整密钥、完整请求头、客户隐私和供应商敏感返回。

## 12. 待确认项

1. 最终接口前缀使用 `/aivideo` 还是 `/ai/aivideo`。
2. 权限码是否统一使用 `ai:aivideo:*`。
3. `han-job` 是否第一版就承接视频任务轮询，还是先由 `han-aivideo` 内部异步实现。
4. 文件上传后是否能拿到稳定 `sys_file.id`，还是第一版先保存 URL 快照。
5. 火山图片/视频返回结果是 URL、Base64、异步任务 ID 还是多种形式并存，需要以模型实测为准。
