# 牛马协作总规则

本规则是 Han 仓库唯一正式规则文档，覆盖仓库治理、README 治理、文档治理、SQL 治理、部署治理、95 运维治理和协作交付要求。

所有正式规则文件必须为 UTF-8 编码，禁止乱码。

## 1. 基本要求

- 统一使用中文沟通
- 所有新增或重写文档必须使用 UTF-8 编码
- 不得在未获明确授权时删减已有能力、边界处理、补偿逻辑或错误分支
- 允许重构和整理，但不允许以“整理”为名做能力缩水
- 正式交付必须附带变更说明和验证结果

## 2. README 规则

- `README.md` 是项目正式大入口
- README 必须包含项目简介、核心特性、架构设计、三档部署、快速开始、文档导航
- README 不得退化成纯导航页
- 正式入口变化时必须同步更新 README

## 3. 文档规则

- `docs/` 是唯一正式文档入口
- 正式文档收敛为少量大手册，不再长期拆成大量碎文档
- 正式文档文件名使用中文
- 旧文档、阶段性报告、流程图、一次性排障记录必须进入 `docs/archive/`
- 不得继续在 `doc/` 中新增正式文档

## 4. 规则文档规则

- 正式规则只保留这一份总规则文档
- 不再长期维护多份治理规则作为正式结构
- 新增约束时必须同步回写本文件

## 5. SQL 规则

- `sql/` 是唯一正式 SQL 入口
- 初始化脚本按 tier 收敛为：
  - `sql/tiers/small/small-init.sql`
  - `sql/tiers/medium/medium-init.sql`
  - `sql/tiers/full/full-init.sql`
- 每档 Nacos 导入脚本收敛为：
  - `small-nacos-derby-import.sql`
  - `medium-nacos-derby-import.sql`
  - `full-nacos-derby-import.sql`
- 升级脚本只允许进入 `sql/upgrades/postgres/`
- 历史 SQL 只允许进入 `sql/archive/`
- 禁止继续把散装 SQL 放回根目录或重新拆成过细模块目录

## 6. 部署规则

- `deploy/` 是唯一正式部署入口
- 三档正式入口固定为：
  - `deploy/small`
  - `deploy/medium`
  - `deploy/full`
- 根目录旧 compose 只允许短期过渡，不得继续作为长期正式入口
- secrets 不得写入 Git

## 7. 分支与发布规则

- `master` 是唯一长期分支
- 临时分支仅用于短期开发或隔离验证
- 临时分支合并后必须删除
- 禁止在 detached HEAD 上形成正式交付
- 95 发布只能从 `master` 产出

## 8. 95 规则

- 95 只允许从 `/opt/han/repo/Han` 与 `/opt/han/deploy/{small,medium,full}` 发布
- 禁止再创建 `Han-xxxx-日期` 形式的临时发布源码目录
- 禁止继续使用 `/opt/han/source/Han-*` 或 `/opt/han/docker` 作为正式入口
- 发布必须记录来源提交、部署目录、验证结果和残留风险

## 9. 产物与临时文件规则

- 禁止提交 `han-ui/dist`
- 禁止提交 `.m2`、`.codex-temp`、日志、压缩包、测试输出
- 允许临时文件在本地存在，但在正式提交前必须剔除

## 10. 同步更新规则

- 任意涉及文档结构的变更，必须同步更新 `docs/index.md`
- 任意涉及 SQL 落位的变更，必须同步更新 `sql/README.md`
- 任意涉及部署结构的变更，必须同步更新部署手册
- 任意发布到 95 的变更，必须同步更新测试与运维手册中的验证口径

## 11. 验证规则

- 结构整理完成后必须至少执行结构检查脚本
- 涉及前端、部署、联调或页面行为时，必须给出最小验证结果
- 涉及 SQL 重构时，必须验证新 SQL 可以在干净环境直接导入
- 未验证部分必须明确说明，禁止默认“应该没问题”

## 12. 不可协商项

- 不得默默删功能
- 不得默默改边界
- 不得把临时文件、产物和旧流程混回正式入口
- 不得绕开正式目录在 95 上继续堆临时部署
- 不得新增乱码文档或双份口径文档
