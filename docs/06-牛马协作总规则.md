# 牛马协作总规则

本文件是 Han 仓库唯一正式规则文档，覆盖仓库治理、README 治理、文档治理、SQL 治理、部署治理、95 运维治理、协作交付要求和 Codex 分层协作资产的使用边界。

所有正式规则文件必须为 UTF-8 编码，禁止乱码。

## 1. 文件定位

- 本文件是 Han 仓库的最高项目规则。
- `AGENTS.md` 是工作区认知核心，用于告诉 Codex 如何进入本仓库。
- `niumma-rules.md` 是分层规则索引，用于按任务类型加载 `.codex` 下的执行资产。
- `.codex/` 是协作资产目录，承载 rules、hooks、skills、agents、memory。
- `.codex/` 不是第二套正式规则；其中任何长期约束要成为正式口径，必须同步回写本文件。

## 2. 基本要求

- 全程使用中文沟通。
- 所有新增或重写文档必须使用 UTF-8 编码。
- 不得在未获明确授权时删减已有能力、边界处理、补偿逻辑或错误分支。
- 允许重构和整理，但不允许以“整理”为名做能力缩水。
- 正式交付必须附带变更说明、验证结果、未验证项和残留风险。
- 结论必须绑定证据来源：代码、文档、日志、测试、配置、线上指标或官方文档。
- 未验证、未执行、未确认的内容，不得表述为已完成。

## 3. 加载顺序

1. 系统指令、开发者指令、用户明确指令。
2. 根级 `AGENTS.md`。
3. 本文件：`docs/06-牛马协作总规则.md`。
4. 根级 `niumma-rules.md`。
5. 当前任务命中的路径级 `AGENTS.md`。
6. `.codex/rules/`、`.codex/hooks/`、`.codex/skills/` 中与任务类型匹配的执行资产。
7. `README.md`、`docs/`、`sql/README.md`、部署手册、测试手册、运维手册、模块 README（当前仓库尚未建立任何模块级 README，补齐后适用）和代码注释。

发现冲突时，以本文件为准；不得绕开本文件另立口径。

## 4. 协作红线

- 不允许伪完成、伪测试、伪结论、伪引用。
- 不知道就查；查不到就明确说不确定。
- 不把推测说成事实，不把建议包装成结论。
- 不重复同一结论灌水，不用空泛套话替代证据。
- 不做与当前目标无关的大重构、大搬家、大面积格式化。
- 不默默删功能，不默默改边界，不默默合并导致行为缩水的业务路径。
- 同一问题第二次修改前，必须先复盘上次失败原因。

## 5. 正式入口规则

- 正式入口固定为：
  - `README.md`
  - `docs/`
  - `sql/`
  - `deploy/`
- README 是项目正式大入口，必须包含项目简介、核心特性、架构设计、三档部署、快速开始、文档导航。
- README 不得退化成纯导航页。
- `docs/` 是唯一正式文档入口。
- `sql/` 是唯一正式 SQL 入口。
- `deploy/` 是唯一正式部署入口。

## 6. 文档规则

- 正式文档收敛为少量大手册，不再长期拆成大量碎文档。
- 正式文档文件名使用中文。
- 旧文档、阶段性报告、流程图、一次性排障记录必须进入 `docs/archive/`。
- 不得继续在 `doc/` 中新增正式文档。
- 任意涉及文档结构的变更，必须同步更新 `docs/index.md`。
- 新增文档前必须先检查是否已有承载同类内容的正式文档；能补充就补充，不能补充再新增。
- 禁止为同一主题反复新建“最终版”“新版”“补充版”“说明版”这类重复文档。

## 7. 规则文档规则

- 正式规则只保留本文件这一份总规则文档。
- 不再长期维护多份治理规则作为正式结构。
- `AGENTS.md`、`niumma-rules.md`、`.codex/` 可以作为执行辅助资产，但不能替代本文件。
- 新增长期约束时必须同步回写本文件。

## 8. SQL 规则

- 初始化脚本按 tier 收敛为：
  - `sql/tiers/small/small-init.sql`
  - `sql/tiers/small/small-init-mysql.sql`
  - `sql/tiers/medium/medium-init.sql`
  - `sql/tiers/full/full-init.sql`
- 每档 Nacos 导入脚本收敛为：
  - `small-nacos-derby-import.sql`
  - `medium-nacos-derby-import.sql`
  - `full-nacos-derby-import.sql`
- PostgreSQL 保持默认数据库；MySQL 8.4 作为正式可选数据库，当前只开放经过独立入口和门禁覆盖的 `small` 档。
- 运行时数据库只通过 JDBC URL 识别方言；禁止在公共 MyBatis 配置中写死 PostgreSQL 或 MySQL。
- PostgreSQL 升级脚本只允许进入 `sql/upgrades/postgres/`；MySQL 增量目录在首个经实库演练的增量脚本出现前不得空建或伪造支持。
- 历史 SQL 只允许进入 `sql/archive/`。
- 禁止继续把散装 SQL 放回根目录或重新拆成过细模块目录。
- 任意涉及 SQL 落位的变更，必须同步更新 `sql/README.md`。
- 涉及 SQL 重构时，必须验证新 SQL 可以在干净环境直接导入。
- 标记某个 tier 支持某种数据库前，必须同时具备初始化 SQL、部署入口、结构门禁和干净实例导入证据。

## 9. 部署规则

- 三档正式入口固定为：
  - `deploy/small`
  - `deploy/medium`
  - `deploy/full`
- 根目录旧 compose 只允许短期过渡，不得继续作为长期正式入口。
- secrets 不得写入 Git。
- 任意涉及部署结构的变更，必须同步更新部署手册。
- 未明确部署目标、覆盖策略、启动方式、回滚方案前，不得执行部署或覆盖操作。

## 10. 分支与发布规则

- `master` 是唯一长期分支。
- 临时分支仅用于短期开发或隔离验证。
- 临时分支合并后必须删除。
- 禁止在 detached HEAD 上形成正式交付。
- 95 发布只能从 `master` 产出。

## 11. 95 规则

- 95 只允许从 `/opt/han/repo/Han` 与 `/opt/han/deploy/{small,medium,full}` 发布。
- 禁止再创建 `Han-xxxx-日期` 形式的临时发布源码目录。
- 禁止继续使用 `/opt/han/source/Han-*` 或 `/opt/han/docker` 作为正式入口。
- 发布必须记录来源提交、部署目录、验证结果和残留风险。
- 任意发布到 95 的变更，必须同步更新测试与运维手册中的验证口径。

## 12. 产物与临时文件规则

- 禁止提交 `han-ui/dist`。
- 禁止提交 `.m2`、`.codex-temp`、日志、压缩包、测试输出。
- 允许临时文件在本地存在，但在正式提交前必须剔除。
- `.codex/` 是规则资产目录，允许入库；`.codex-temp/` 和 `.codex-tmp/` 仍视为临时目录，不得提交。

## 13. 技术与接口边界

- Han 后端以 Java 21、Spring Boot、Spring Cloud、Maven 为主。
- Han 前端以 Vue 3、TypeScript、Vite 为主。
- AI 短剧 / AIVideo 相关开发必须先读取 `docs/08-AI短剧开发手册.md`，再进入代码、SQL、前端、配置或联调实现。
- 已有系统能力必须优先复用：字典、模型管理、Prompt 模板、文件、异步任务、权限、租户、配置、审计、用量统计等，不得在业务模块中另写平行硬编码能力。
- 需要新增枚举、模型类型、模板分类、状态、策略或配置项时，优先落到对应字典、配置、模板或模型管理模块；如需人工录入，交付必须给出可直接录入的数据清单。
- 新增跨服务调用优先使用 `@HttpExchange`。
- 新增 JSON 处理优先使用 Jackson，禁止随意引入 Gson、Fastjson、Fastjson2。
- 新增对象转换优先通过 MapStruct 或 Converter 层收口。
- 修改公共模块时必须保持公共扩展性，做好 DTO、Service、Client、Converter、组件或工具函数封装，保证其他模块可以公共调用。
- 公共模块不得只为单一业务场景硬改；短剧专属规则应留在 `han-aivideo` 编排层，公共模块只沉淀可复用能力、兼容入口、默认行为和错误边界。
- 管理端接口维持当前项目的 `GET / POST` 风格，不为追求形式破坏兼容。
- A/I/B 控制器分层必须保留：B 层不标 `@RestController`，A 层面向管理端并显式权限控制，I 层面向内部调用并显式内部鉴权。
- 对外接口属于调用契约；未经确认，不得静默更改语义、返回结构或兼容行为。

## 14. 高风险操作规则

- 下载、安装、打包、部署、发版属于高风险操作。
- 改配置、启停服务、操作数据库属于高风险操作。
- 写系统目录、共享目录、外接磁盘属于高风险操作。
- 删除、替换、迁移、覆盖、回滚属于高风险操作。
- 处理密钥、令牌、PII、客户数据属于高风险操作。
- 以上动作只要目标环境、盘符、目录、版本、来源、覆盖范围、回滚方式不明确，一律先确认。

## 15. 验证规则

- 结构整理完成后必须至少执行结构检查脚本。
- 涉及前端、部署、联调或页面行为时，必须给出最小验证结果。
- 涉及 SQL 重构时，必须验证新 SQL 可以在干净环境直接导入。
- 不允许只跑正常路径就报完成。
- 不允许跳过失败测试而不说明。
- 不允许只看代码不看实际运行结果。
- 未验证部分必须明确说明，禁止默认“应该没问题”。

## 16. 交付规则

交付时必须说明：

- 改了什么。
- 验证了什么。
- 还有什么未验证或残留风险。
- 涉及高风险操作时，必须说明回滚思路或门禁条件。
- 若无法执行测试、部署或访问某资源，必须说明阻塞点和潜在风险。

## 17. 输出与表达规则

本节约束回复给用户的文字，不约束代码注释和文档正文。

### 17.1 结论先行

- 第一句必须回答「结果是什么」或「发现了什么」，即用户只看一句时想知道的那件事。
- 过程、推理、证据放在结论之后，供需要的人往下读。
- 禁止用铺垫开头（"好的，我来……""接下来我将……"）。

### 17.2 精简优先

- 靠**删内容**做短，不靠压缩句子。删掉不影响用户下一步决策的细节。
- 不复述用户已知信息，不重复上一条回复讲过的内容。
- 同一件事只说一遍；已说清的结论不再换个说法重申。
- 中间过程只在改变方向或发现关键事实时汇报，不逐步播报。

### 17.3 展示方式

- 简单问题用直接的散文回答，不套标题和分节。
- 需要分节时，标题要能独立看懂，让用户可以只读感兴趣的那节。
- 表格只用于短小可枚举的事实（对照、清单、矩阵）；解释性内容写在表外。
- 命令、路径、文件名、权限串、类名方法名一律用反引号包起来。
- 关键数字和结论用粗体，但同一段落里不超过一处，否则等于没有重点。
- 长清单按重要性排序，最重要的在最前面。

### 17.4 不要做的事

- 不写与用户决策无关的自我评价、反省和过程叙述。
- 不为了显得严谨而堆砌免责声明。
- 不用箭头链（`A → B → 失败`）代替句子。
- 不自造缩写和代号后让用户回头对照。

## 18. 记忆与演化规则

- `.codex/memory/corrections.jsonl` 记录用户对行为、规则、输出方式的纠正。
- `.codex/memory/observations.jsonl` 记录仓库现状、流程痛点、重复问题。
- `.codex/memory/learned-rules.md` 存放多次出现的问题提炼出的规则候选。
- `.codex/memory/evolution-log.md` 记录规则工程化变更、结构调整和落地结果。
- 记忆内容不得包含密钥、令牌、客户隐私或未脱敏敏感信息。
- 记忆只能辅助执行；正式约束必须回写本文件。

## 19. 不可协商项

- 不得默默删功能。
- 不得默默改边界。
- 不得默默弱化错误处理、补偿逻辑或兼容路径。
- 不得把临时文件、产物和旧流程混回正式入口。
- 不得绕开正式目录在 95 上继续堆临时部署。
- 不得新增乱码文档或双份口径文档。
