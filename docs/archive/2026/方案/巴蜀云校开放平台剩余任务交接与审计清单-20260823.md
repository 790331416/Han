# 巴蜀云校开放平台剩余任务交接与审计清单

## 1. 用途与结论

本文用于把开放平台剩余收口工作交给其他执行模型，主模型只负责代码审计、证据复核和最终放行。

当前不是“功能还没做完”，而是“功能已经上线，尚有交付收口和安全强化未完成”：

- T05-R3、T06、T07、T08、T09 已按原方案完成并通过现有自动化、实库和生产主链路验证。
- 最终功能基线为 `f06c96dc4098de4fbf429a93bdc1afcf00d1a1e5`。
- 后端最终统一测试 476 项通过；开放平台 58/58 个逻辑 Handler 已有契约覆盖；管理端 Playwright 11/11 通过。
- 厂商注册、审核、应用、SANDBOX/PROD 授权、凭证、Token、三条目录、调测、轮换、撤销、暂停和数据清理已在生产主链路验证。
- `/manage/` 基路径、静态资源和公开厂商申请页已用真实 Chromium 验证；尚未完成管理员登录后的四个管理页面人工验收。
- 生产仍沿用 HTTP，HTTPS 尚未配置；不能宣称已达到公网 TLS 安全发布标准。

完整架构、开发过程、测试矩阵、生产制品、备份、故障恢复与清理证据见[《巴蜀云校开放平台全流程实施与上线方案》](巴蜀云校开放平台全流程实施与上线方案-20260823.md)。

## 2. 是否按原方案实施

是。主线始终按 `T05-R3 → T06 → T07 → T08 → T09 → 生产验收` 推进，目录、厂商、应用、授权、凭证、运行时鉴权、调测和兼容性边界未改变。

生产门禁发现的以下问题属于原方案中“真实环境验证、失败回滚、根因修复”的必要结果，不是另起一套架构：

1. JSON 映射器缺失。
2. 缺失 Bearer Token 的错误包装不明确。
3. 内部签名运行时密钥未绑定。
4. 跨服务时间格式不一致。
5. 授权响应缺少环境维度。
6. 管理端生产基路径与 favicon 不匹配。

这些问题均已按共享根因修复并留有回归，不得重新引入 Basic 并行鉴权、第二套用户体系或第二套接口目录。

## 4. 执行任务说明

### 4.1 C01 管理员登录后页面验收

目标页面：

- `/manage/open/app`
- `/manage/open/api-resource`
- `/manage/open/vendor`
- `/manage/open/authorization`

执行要求：

1. 使用用户在运行时提供的管理员账号和密码；凭据不得写入代码、脚本、环境文件、文档、截图、日志或模型报告。
2. 必须从真实登录页完成登录。若页面仍没有密码输入框，先记录实际 DOM、路由、截图、控制台和网络结果，不得用手工注入 Token 冒充“登录成功”。
3. 逐页验证菜单可见、路由可达、空态或列表正常、按钮权限符合管理员角色。
4. 记录非预期 HTTP 4xx/5xx、业务 `code != 200`、`requestfailed`、`pageerror` 和 `console error`。
5. 本任务只读，不新增厂商、应用、资源版本、Grant 或凭证，不修改正式三条资源。
6. 每页至少保留一张脱敏截图和一份简短结果表。

通过标准：四页均可由真实管理员会话访问，页面关键内容可见，无非预期控制台错误或失败请求；若任一页失败，报告具体接口、状态码、业务码和页面表现。

### 4.2 C02 接口测试证据总账

以代码中的实际 Controller/Handler 和路由为源，建立一张不重不漏的映射表，每个接口至少记录：

- 模块、Controller、方法、实际路由和认证方式。
- 正例、参数/状态边界、未登录/错误认证、权限/Scope、租户/环境/数据范围、过期/撤销/轮换等适用负例。
- 证据层级：自动化测试、临时数据库、生产只读、生产关键主链路。
- 对应测试类/用例、执行命令、结果和未覆盖原因。

“58/58 逻辑 Handler 契约覆盖”只能证明自动化契约总量；不得直接改写为“58 个生产破坏性接口全部实测”。生产只补安全的只读验证和已批准的沙箱流程，不删除、下线或改动正式三条资源。若发现真正没有任何证据的接口，先补本地/临时库自动化；涉及生产写入时停止并请求审批。

通过标准：每个开放平台 Handler/路由均能追溯到至少一项可复现测试；所有未做生产破坏性验证的接口有明确边界和自动化替代证据。

### 4.3 C03 Git 远端收口

执行顺序：

1. 记录当前分支、工作树和本地 `HEAD`。
2. 只读查询远端同名分支。
3. 若 TLS 仍失败，保留原始错误并停止；不得设置 `http.sslVerify=false`，不得改用不可信代理或明文凭据。
4. 若远端可达，先判断是否分叉；远端有新提交时停止并报告，不得强推。
5. 仅在无分叉时执行普通 push。
6. push 后再次查询远端，证明远端哈希等于最终本地 `HEAD`。

通过标准：远端分支与最终本地提交完全一致。网络阻断只能记为“仍阻塞”，不能记为已交付。

### 4.4 C04 HTTPS 与 auth 密钥边界安全专项

第一阶段只读盘点：

- 公网入口、边缘代理、上游管理端和网关的真实拓扑。
- 现有 80/443 监听、防火墙、域名解析和证书状态。
- Nginx 配置来源、加载顺序、备份位置和回滚命令。
- OAuth discovery issuer、CORS、Cookie、回调地址和调测台对协议的依赖。
- 当前 auth 实际副本数和注册 RSA 密钥来源。当前证据显示为单副本时，应明确记录“禁止在未配置共享受控 RSA 密钥前扩容”；若已是多副本，必须逐副本证明使用同一受控配置并完成公钥注册回归。

实施前门禁：

- 明确证书来源、续期责任、变更窗口、目标域名和 443 放行状态。
- 对 Nginx 配置和证书目录建立可读备份并校验。
- 明确 HTTP 到 HTTPS 的切换/跳转策略和一条可立即执行的回滚路径。
- 获得用户明确批准；只读盘点不等于授权签发证书、改配置或重启服务。

实施后最小复测：

- 证书链、域名、有效期和 TLS 握手正常。
- HTTP 跳转策略符合批准结果。
- `/manage/`、登录、四个开放平台页面和静态资源正常。
- OAuth discovery issuer、CORS、Token、自省、UserInfo、三条目录和在线调测正常。
- auth 每个实际副本的公钥获取与注册链路正常，负载切换不导致密文无法解密。
- 浏览器无 mixed content、证书、控制台或请求失败。

### 4.5 C05/C06 独立历史债务

- C05 只处理 PostgreSQL full 初始化中的既有 AIVideo `setting_id` 空值问题；先证明根因和影响范围，再做最小修复，只在临时 PostgreSQL 实例执行首次和重复初始化。
- C06 只处理部署结构检查指出的既有 SDFZ MySQL 脚本挂载问题；不得删除脚本、放宽检查器或虚构 medium/full MySQL 支持。
- 两项必须使用独立提交和独立报告，不得与开放平台收口提交混合。

## 5. 禁止重做和禁止操作

- 不重复执行已经完成的生产 MySQL 开放平台迁移和正式种子写入。
- 不重新创建已清理的生产 E2E 厂商、账号、应用、授权、凭证或调测记录。
- 不修改、下线或删除正式三条接口资源及其已发布版本，只为追求“生产所有破坏性 CRUD 都跑一遍”。
- 不重新引入 Basic Auth 过滤器、平行鉴权链路、第二套账号系统或第二份资源目录。
- 不把 HTTPS 未完成包装成“公网安全已完成”，也不因 HTTPS 未完成否定已经验证的 HTTP 功能上线。
- 不在脏工作区批量暂存、格式化、回退或提交无关教育模块和系统页面改动。
- 不提交 `dist`、JAR、压缩包、日志、测试输出、截图中的敏感信息或任何凭据。
- 不强推、不关闭 Git TLS 校验、不在未备份时改 Nginx/数据库/服务。

## 6. 推荐的多模型分工

后续执行主模型可自行并行安排最多三个子模型：

| 子模型 | 独占职责 | 允许输出 | 禁止事项 |
|---|---|---|---|
| 子模型 A | C01 浏览器与管理端只读验收 | 截图、页面/接口结果、失败清单 | 改代码、写业务数据、绕过真实登录 |
| 子模型 B | C02 接口测试证据总账 | Handler/路由/正负例/证据映射和缺口 | 用生产破坏性操作凑覆盖率 |
| 子模型 C | C03 Git 远端诊断与安全推送 | 分支/哈希/错误证据 | 强推、关闭 TLS 校验、改无关文件 |

第一轮完成后再复用空闲子模型执行 C04 只读盘点和 C05/C06 独立债务审计。执行主模型负责去重、文件所有权、生产变更串行化和结果整合。任何子模型报告都只是待审核材料，不能直接宣布完成。

## 8. 主模型审计门禁

主模型不按执行模型的“完成报告”直接放行，必须检查实际状态：

1. **差异边界**：查看真实 `git diff`、未跟踪文件、提交内容和文件所有权；拒绝无关改动、凭据、生成物和宽泛重构。
2. **测试证据**：复跑命中检查；任何失败、跳过或数量下降必须解释。代码变化时按风险重跑受影响模块，不能只跑编译。
3. **浏览器证据**：检查真实登录、四页截图、页面 DOM、请求与控制台；打开页面不等于功能通过。
4. **远端证据**：比较最终本地 `HEAD` 与远端同名分支哈希；只有一致才能记为已推送。
5. **安全证据**：检查报告、提交、日志和截图不含账号、密码、Token、Secret、私钥或数据库凭据。
6. **生产证据**：有生产变更时核对变更前备份、精确目标、变更后回读、健康状态和回滚可用性。
7. **严重级别**：鉴权绕过、跨租户/跨环境、敏感信息泄露、数据损坏、服务不可用为 P0；页面不可用、权限/菜单错误、测试或推送不完整为 P1；文档和独立基线债务为 P2。

只有 C01、C02、C03 的证据通过且无相关 P0/P1 未关闭项，主模型才可判定“开放平台功能与交付收口完成”。C04 完成后，才能进一步宣称“公网 HTTPS 安全发布完成”。
