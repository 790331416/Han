# Han 从零到最终效果

## 1. 文档目的

这份文档只梳理当前已经开发并且已经在 `95` 真环境测绿的主链路，不把未开发、诚实占位和历史猜测混在一起。

使用口径：

- 以 `2026-04-08` 当前仓库与 `95` 在线回归结果为准
- 顺序按“真实前置依赖 + 最少回头路”的方式编排，不按左侧菜单顺序硬排
- 只写当前能走通到“最终效果”的链路
- 未开发或部分开发边界单独标注，不冒充已完成

## 2. 环境入口与分层关系

- `small`：`http://10.18.35.95:3100`
- `medium`：`http://10.18.35.95:3200`
- `full`：`http://10.18.35.95:3000`

分层关系：

- `small = 核心系统 + 通知 + 任务调度 + 基础监控`
- `medium = small + 租户 + 工作流 + 开放平台 + OSS`
- `full = medium + 代码生成 + AI`

一句话理解：

- 先把 `small` 跑通，才有基础后台能力
- 再上 `medium`，补齐多租户和对外开放能力
- 最后在 `full` 里补代码生成与 AI 最终效果

## 4. 全项目总顺序

按当前最稳的演示和验证顺序，建议这样走：

1. 环境与登录起手
2. `small` 核心后台闭环
3. `medium` 增量业务闭环
4. `full` 非 AI 增量闭环
5. `full AI` 从资源准备到最终效果闭环

如果你是手测，照这个顺序最不容易走回头路。

## 9. 第五段：Full AI 从零到最终效果

这一段最容易误解。当前实现里，`/ai/application` 不是第一步创建源头，它更像应用工作台和聚合入口。  
真正的顺序是先准备 AI 资源，再创建智能体或工作流，再发布，最后才进入应用详情页和聊天页看最终效果。

### 9.1 AI 总顺序

1. 先建模型
2. 按需要建知识库
3. 按需要建 MCP
4. Prompt 模板按需要补，不是硬前置
5. 再建智能体或工作流
6. 发布
7. 最后去应用详情页或聊天页看最终效果

### 9.2 第一步：模型

先做什么：

- 进入 `/ai/model`
- 确认已有可用模型
- 测试连通

为什么它必须最先：

- 智能体和工作流都会依赖 `modelId`

最终效果：

- 后续 AI 资源可以被真正绑定和运行

当前测试状态：

- 已通过
- 证据：[ai-model.spec.ts](../../../../han-ui/tests/e2e/specs/ai-model.spec.ts) `1 passed`

### 9.3 第二步：知识库

先做什么：

- 进入 `/ai/knowledge`
- 创建知识库
- 上传 `txt / md / html` 文档
- 重建索引或命中测试

什么时候必须做：

- 当你想在最终聊天效果里看到 `knowledgeSources` 时，这是硬前置

最终效果：

- 聊天回答除了正文，还能带来源片段

当前测试状态：

- 已通过
- 证据：[ai-admin-deep.spec.ts](../../../../han-ui/tests/e2e/specs/ai-admin-deep.spec.ts)、[ai-admin-lifecycle.spec.ts](../../../../han-ui/tests/e2e/specs/ai-admin-lifecycle.spec.ts)、[ai-chat-structured-meta.spec.ts](../../../../han-ui/tests/e2e/specs/ai-chat-structured-meta.spec.ts)

### 9.4 第三步：MCP

先做什么：

- 进入 `/ai/mcp`
- 创建 MCP 服务
- 刷新工具
- 确认工具元数据可见

什么时候必须做：

- 当你想在最终聊天效果里看到 `toolExecutions` 时，这是硬前置

最终效果：

- 聊天回答除了正文，还能展示工具调用轨迹

当前测试状态：

- 已通过
- 证据：[ai-admin-deep.spec.ts](../../../../han-ui/tests/e2e/specs/ai-admin-deep.spec.ts)、[ai-admin-lifecycle.spec.ts](../../../../han-ui/tests/e2e/specs/ai-admin-lifecycle.spec.ts)、[ai-admin-extended.spec.ts](../../../../han-ui/tests/e2e/specs/ai-admin-extended.spec.ts)、[ai-chat-structured-meta.spec.ts](../../../../han-ui/tests/e2e/specs/ai-chat-structured-meta.spec.ts)

### 9.5 第四步：Prompt 模板

先做什么：

- 进入 `/ai/prompt`
- 创建或编辑模板
- 预览变量渲染

它在主链路中的位置：

- 它是可复用的提示词资产，不是“先没有它就完全走不通”的硬前置

最终效果：

- 你可以把 Prompt 管理能力补齐，但不会改变“模型优先”的主顺序

当前测试状态：

- 已通过
- 证据：[ai-admin-deep.spec.ts](../../../../han-ui/tests/e2e/specs/ai-admin-deep.spec.ts)、[ai-admin-lifecycle.spec.ts](../../../../han-ui/tests/e2e/specs/ai-admin-lifecycle.spec.ts)、[ai-admin-extended.spec.ts](../../../../han-ui/tests/e2e/specs/ai-admin-extended.spec.ts)

### 9.6 第五步：智能体或工作流

先做什么：

- 进入 `/ai/agent` 或 `/ai/workflow`
- 绑定模型
- 按需要绑定知识库和 MCP

推荐怎么选：

- 想最快看到回复：优先建智能体或简单工作流
- 想看到完整结构化效果：优先建工作流，并绑定知识库与 MCP

最终效果：

- AI 应用的真正运行载体被创建出来

当前测试状态：

- 已通过
- 证据：[ai-application.spec.ts](../../../../han-ui/tests/e2e/specs/ai-application.spec.ts) 证明应用首页创建入口会正确跳入智能体和工作流管理页

### 9.7 第六步：发布

先做什么：

- 把智能体或工作流发布出去

为什么这一步不能省：

- 不发布，就很难进入“应用详情页可访问、访问入口可用、最终效果稳定展示”的状态

最终效果：

- 应用详情页具备发布态
- 可以从详情页或访问入口继续走后续验证

当前测试状态：

- 已通过
- 证据：[ai-application-detail.spec.ts](../../../../han-ui/tests/e2e/specs/ai-application-detail.spec.ts)

### 9.8 第七步：应用详情页与聊天最终效果

先做什么：

- 从 `/ai/application` 进入应用详情页
- 查看概览、设置、调试、发布、访问入口、日志
- 再进入 `/ai/chat`

最终效果分三档：

- 只绑定模型：能正常对话
- 模型 + 知识库：能看到 `knowledgeSources`
- 模型 + MCP：能看到 `toolExecutions`
- 模型 + 知识库 + MCP：能同时看到来源洞察和工具轨迹，这是当前 AI 最完整效果

当前测试状态：

- 已通过
- 证据：
  - [ai-application.spec.ts](../../../../han-ui/tests/e2e/specs/ai-application.spec.ts) `2 passed`
  - [ai-application-detail.spec.ts](../../../../han-ui/tests/e2e/specs/ai-application-detail.spec.ts) `1 passed`
  - [ai-chat-structured-meta.spec.ts](../../../../han-ui/tests/e2e/specs/ai-chat-structured-meta.spec.ts) `1 passed`
  - Full AI 专项整包 `25 passed`

## 12. 最终结论

按当前真实状态，整套项目的推荐顺序可以压缩成一句话：

`登录 -> small 核心后台 -> medium 增量业务 -> full 代码生成 -> AI 模型 -> 知识库 / MCP -> 智能体或工作流 -> 发布 -> 应用详情页 / 聊天最终效果`

并且这条顺序上当前已经测绿的内容包括：

- `small` 主链路
- `medium` 主链路
- `full` 主链路
- `full AI` 主链路

所以你现在如果要手测，最稳的方式就是沿着这份顺序往下点，而不是按菜单随机穿插。
