# 仓库全局整理与95重建执行计划

## 摘要

本次整理以“主线唯一、三档优先、文档中文化、规则可阻断、95 全新重建”为总原则，目标是一次性解决当前仓库与 95 环境中的四类问题：源码主线不干净、文档与 SQL 散落、规则口径不闭环、95 发布目录与运行残留失控。

本次执行完成后的正式交付物固定为：

- `docs/00-治理/仓库全局整理与95重建执行计划.md`
- `docs/00-治理/牛马协作规则.md`
- `docs/index.md`
- `sql/README.md`
- `deploy/` 下三档正式部署入口
- `scripts/checks/` 下结构与规则检查脚本
- CI 中的目录与交付阻断校验

本次不计划修改业务接口语义；对外“接口”层面的变化仅包括仓库正式入口、文档入口、SQL 入口、部署入口和 95 发布入口的统一收口。

## 关键变更

### 1. Git 主线与分支收口

- 以 `master` 作为唯一长期分支；本地和远端最终只保留 `master`
- 当前工作区的脏改动纳入收口，但先剔除 `dist`、缓存、日志、压缩包、临时验证文件
- 彻底消除 detached HEAD 状态，当前工作区最终必须重新附着到 `master`
- 删除所有短生命周期分支与历史验证分支
- 任何可交付结果不得在 detached HEAD 上形成

### 2. 文档扫描、整理、合并与中文命名

- `doc/` 退役，不再作为正式入口；所有当前有效内容迁入 `docs/`，历史材料进入 `docs/归档/`
- `docs/` 内所有正式分类目录改为中文命名，所有正式文档文件名统一改为中文
- `README.md` 从“流水账”改为“导航页 + 当前正式入口说明”
- 部署类、测试类、架构类文档分别合并进入对应正式目录
- AI 专项分析、阶段性验证报告、流程图、一次性故障说明统一转入 `docs/归档/2026/`
- 原 `docs/niuma-assistant-rules.zh-cn.md` 按 UTF-8 重建并替换为正式中文规则文档

### 3. SQL 全局重排

- SQL 以 `tiers/small|medium|full` 为主视图，不再散放在 `sql/` 根目录
- 每个 tier 下按代码模块分目录，初始化脚本统一按模块落位
- 每个模块初始化脚本统一拆分为 `00-schema.sql`、`10-seed.sql` 和可选 `90-fixup.sql`
- 每个 tier 固定包含 `manifest.md`、`nacos/derby-import.sql` 和 `postgres/<module>/...`
- 共享 SQL 进入 `sql/shared/`
- 增量升级脚本只允许进入 `sql/upgrades/postgres/`
- 旧散装 SQL 在完成迁移后进入 `sql/archive/` 或删除

### 4. 牛马规则重构与补强

执行后，牛马规则会覆盖：

- 仓库治理
- 文档治理
- SQL 治理
- 发布治理
- 95 运维治理
- UTF-8 编码要求
- 产物与分支清理要求
- 文档索引、manifest、验证记录的同步义务

### 5. 规则落地为脚本与 CI

新增检查脚本并接入 CI：

- `check-repo-layout`
- `check-doc-layout`
- `check-sql-layout`
- `check-no-generated-files`
- `check-deploy-layout`

CI 固定阻断以下问题：

- 新增文档未归位到 `docs/` 或未入索引
- 新增 SQL 未进入 tier/module 正式目录
- 提交了 `dist`、缓存、日志、压缩包等产物
- 新增根目录散装文件违反白名单
- 发布或部署文件未进入 `deploy/` 正式目录

### 6. 95 全清重建

- 清理 `/opt/han/source` 下所有历史验证目录
- 清理 `/opt/han/docker` 下散装 compose、bak 与临时入口
- Han 相关容器、镜像、网络、volume 按全新环境重建
- `maxkb` 从 Han 正式交付链中解耦，所需密钥改入新的 secrets 位置
- 重建后只保留三档正式部署目录和对应运行入口

## 实施顺序

### 阶段 1：盘点与主线收口

- 盘点当前脏改动并形成“保留 / 删除 / 归档”清单
- 清理产物类与临时类文件
- 将应保留的源码、文档、SQL、部署变更分批整理为正式提交
- 收口到 `master`
- 清理本地与远端剩余分支
- 将当前工作区安全附着回 `master`

### 阶段 2：文档体系重建

- 建立 `docs/` 中文分类目录和 `index.md`
- 迁移并合并当前有效文档
- 将历史资料归档到 `docs/归档/2026/`
- 重写 `README.md`
- 重建 UTF-8 的正式牛马规则文档

### 阶段 3：SQL 与部署结构重建

- 建立 `sql/shared`、`sql/tiers`、`sql/upgrades`、`sql/archive`
- 将现有 PostgreSQL 初始化脚本按 tier/module 迁移
- 将 Nacos Derby 脚本迁入各 tier 正式位置
- 为每个 tier 建立 `manifest.md`
- 新建 `deploy/small`、`deploy/medium`、`deploy/full`
- 将根目录和 95 现有散装 compose 规范化迁入 `deploy/`

### 阶段 4：规则阻断化

- 新增规则检查脚本
- 新增 CI 工作流
- 将“文档、SQL、部署、产物、分支”治理规则接入自动校验
- 对仓库执行一次全量结构校验，修复剩余违规点

### 阶段 5：95 全清重建与验证

- 备份必要 secrets 与重建所需最小信息
- 清理 95 上旧 Han 容器、镜像、网络、volume、源码目录、部署目录
- 按新目录结构重建 `repo`、`deploy`、`logs`、`backups`
- 按新的 SQL 结构重建 `small / medium / full`
- 重新导入 Nacos 配置、重建 PostgreSQL 初始化数据、重新部署三档服务
- 按固定验证清单完成 95 回归并留档

## 测试与验收标准

### 仓库侧验收

- `git branch --all` 仅剩 `master` 和 `origin/master`
- 当前工作区附着于 `master`
- 根目录不存在散装阶段性文件和生成产物
- `doc/` 不再作为正式文档入口
- `docs/` 内正式分类目录和正式文件名均为中文
- `sql/` 已按 `shared / tiers / upgrades / archive` 固化
- `deploy/` 成为唯一正式部署入口
- 规则检查脚本和 CI 全绿

### 95 侧验收

- `/opt/han/source/Han-*` 历史验证目录全部消失
- `/opt/han/docker` 的旧散装部署方式退役
- 95 上只保留 `/opt/han/repo/Han` 与 `/opt/han/deploy/{small,medium,full}`
- 三档环境均可从新结构独立重建
- Nacos、PostgreSQL、部署文件全部来自新结构
- 主链路、页面级健康回归、Full AI 专项回归按新清单全部通过

### 固定回归清单

- `small`：登录、通知中心、任务调度、页面级健康回归
- `medium`：登录、租户、开放平台、OSS、页面级健康回归
- `full`：登录、代码生成、AI 模型、AI 应用、AI 对话、页面级健康回归、Full AI 专项回归

## 默认值与约定

- 顶层 `docs/` 保留英文，内部正式分类目录与正式文档文件名改为中文
- 代码、SQL、部署等技术根目录不改为中文
- 历史文档默认归档，不默认直接删除
- 当前脏改动默认纳入收口，但先剔除产物和临时文件
- 95 默认按全新环境重建执行，不继承当前 Han 数据
- AI 密钥等 secrets 不进 Git，只进入新的部署 secrets 管理位置
- 本计划是后续执行的唯一主计划文档，实施中新增动作必须回写到本计划和对应规则文档
