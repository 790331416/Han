# 牛马协作规则

本规则是 Han 仓库的正式协作规范，覆盖仓库治理、文档治理、SQL 治理、发布治理、95 运维治理和协作交付要求。所有正式规则文件必须为 UTF-8 编码，禁止乱码。

## 1. 角色与基本要求

- 统一使用中文沟通
- 所有新增或重写的文档必须使用 UTF-8 编码
- 不得在未获明确授权时删减已有能力、边界处理、补偿逻辑或错误分支
- 允许重构和整理，但不允许以“整理”为名做能力缩水
- 正式交付必须附带变更说明和验证结果

## 2. 主线与分支规则

- `master` 是唯一长期分支
- 临时分支只用于短生命周期开发；合并完成后必须立即删除
- 禁止在 detached HEAD 上形成正式交付
- 合并到 `master` 后，必须清理本地与远端临时分支
- 涉及 95 发布的代码，必须先进入 `master`

## 3. 仓库结构规则

- 根目录只允许保留工程入口、构建入口、配置入口和稳定说明文件
- 禁止新增根目录散装 `md`、散装 `sql`、散装 compose、散装测试记录
- `docs/` 是唯一正式文档入口
- `sql/` 是唯一正式 SQL 入口
- `deploy/` 是唯一正式部署入口
- `scripts/checks/` 是唯一结构校验脚本入口

## 4. 文档治理规则

- 正式文档只允许进入 `docs/`
- `docs/` 内正式分类目录和正式文档文件名必须使用中文
- 顶层 `docs/` 保留英文目录名，不再新建第二套文档根目录
- `doc/` 退役，不得继续新增内容
- 历史报告、流程图、一次性排障记录必须归档到 `docs/归档/`
- 新增或重命名正式文档时，必须同步更新 `docs/index.md`
- 同一主题只允许保留一份主文档，旧版本进入归档

## 5. SQL 治理规则

- SQL 主视图固定为 `sql/tiers/<tier>/`
- tier 下固定按 `db -> module` 组织
- PostgreSQL 初始化脚本统一使用 `00-schema.sql`、`10-seed.sql`、可选 `90-fixup.sql`
- 每个 tier 必须有 `manifest.md`
- Nacos 导入脚本必须进入 `sql/tiers/<tier>/nacos/derby-import.sql`
- 升级脚本只允许进入 `sql/upgrades/postgres/`
- 共享模板只允许进入 `sql/shared/`
- 旧散装 SQL 不允许继续作为正式入口，迁移后必须归档或删除

## 6. 部署与 95 运维规则

- 95 只允许从 `/opt/han/repo/Han` 与 `/opt/han/deploy/{small,medium,full}` 发布
- 禁止再创建 `Han-xxxx-日期` 形式的临时发布源码目录
- `maxkb` 不属于 Han 正式发布链路
- secrets 不得写入 Git；只允许进入 95 的持久化环境变量文件或受控 secrets 位置
- 发布必须记录来源提交、部署目录、验证结果和残留风险
- 95 重建或切换时必须遵守固定顺序：基础依赖、网关、业务服务、UI

## 7. 产物与临时文件规则

- 禁止提交 `han-ui/dist`
- 禁止提交 `.m2`、`.codex-temp`、日志、压缩包、测试输出
- 允许临时文件在本地存在，但在正式提交前必须剔除
- 构建产物如需交付，只能通过镜像或正式制品仓库交付，不能直接进入 Git

## 8. 变更同步规则

- 任意涉及文档结构的变更，必须同步更新 `docs/index.md`
- 任意涉及 SQL 落位的变更，必须同步更新对应 `manifest.md` 与 `sql/README.md`
- 任意涉及部署结构的变更，必须同步更新 `deploy/*/init-order.md` 与 `docs/04-部署/*`
- 任意发布到 95 的变更，必须同步更新 `docs/03-测试/95验证运行手册.md`
- 任意新增约束，必须同步更新本规则或其子规则文档

## 9. 验证与留痕规则

- 代码整理完成后必须至少执行结构检查脚本
- 涉及前端、部署、联调或页面行为时，必须给出最小验证结果
- 95 发布必须记录验证入口、通过项、失败项和边界项
- 未验证的部分必须明确标注，禁止口头默认“应该没问题”

## 10. 不可协商项

- 不得默默删功能
- 不得默默改边界
- 不得默默把临时文件、产物和旧流程混回正式入口
- 不得绕开正式目录在 95 上继续堆临时部署
- 不得新增乱码文档或双份口径文档
