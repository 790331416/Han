## 7. Han 技术规范

AI 短剧开发必须遵守：

- 后端主技术栈：Java 21、Spring Boot、Spring Cloud、Maven。
- 前端主技术栈：Vue 3、TypeScript、Vite。
- BOSS 当前 Windows 本机验证工具链固定使用 D 盘路径；进入 `D:\code\Han` 执行 Maven、pnpm、Git、Python、FFmpeg 命令前，先加载 `D:\code\Han\scripts\helpers\use-d-drive-dev-env.ps1`，不得自动从 C 盘工具路径兜底。
- 数据库：PostgreSQL。
- 配置与服务治理：Nacos。
- JSON 处理优先 Jackson，禁止新增 Gson、Fastjson、Fastjson2。
- 服务间调用优先 `@HttpExchange`，禁止新增 Feign。
- 对象转换使用 MapStruct 或 Converter 层收口。
- 管理端接口保持 Han 当前 `GET / POST` 风格。
- 新模块遵守 A/I/B 控制器分层：B 层不标 `@RestController`，A 层显式权限控制，I 层显式内部鉴权。
- SQL 只能进入 `sql/tiers/{small,medium,full}` 或 `sql/upgrades/postgres/`。
- secrets、完整 API Key、数据库密码、Redis 密码、Nacos 密码不得进入 Git。

## 8. 模块边界

- `han-aivideo` 只承载 AI 短剧业务状态和流程编排，包括项目、原文、润色稿、剧本、人物、场景、道具、分镜、媒体资产、生成任务、确认记录。
- `han-ai` 承载通用 AI 能力，包括模型配置、Prompt 模板、文本/图片/视频/TTS 客户端和用量统计。
- `han-file` 承载文件上传、图片、视频、音轨、成片归档和访问。
- `han-job` 承载平台通用调度和异步任务能力；短剧私有状态机留在 `han-aivideo`，不得反向污染通用任务模型。
- `han-aivideo-ui` 承载 `/studio/**` 创作端和 `/ai/aivideo/**` 管理端，并通过 Han 网关复用认证、权限、租户和文件访问。
- `han-ui` 继续承载 Han 通用后台；需要共享的组件应抽取为可复用公共能力，禁止直接复制短剧业务逻辑回通用后台。
- `han-system`、`han-tenant` 继续负责用户、角色、菜单、权限和租户隔离。

## 9. 反哺 Han 原则

AIVideo 开发中发现能让 Han 技术更新、更稳定、更好用的通用能力时，可以作为 Han 升级适配候选。

允许优先反哺：

- 火山文本、图片、视频模型客户端标准化。
- AI 异步任务进度、重试、取消和失败诊断。
- 文件和媒体预览能力。
- Prompt 模板变量、版本和试运行体验。
- 模型用量、成本预估和额度拦截。
- 前端候选选择、任务进度、成本提示组件。
- 95 联调和发布验证脚本。

反哺门禁：

- 不把短剧私有业务规则包装成 Han 通用能力。
- 不静默引入新架构、新依赖或平行服务体系。
- 必须先说明目标、影响范围、验证方式和回滚方式。
- 涉及依赖、SQL、部署、95 发布或配置变更时必须单独确认。

## 9.1 系统能力落位规则

AI 短剧开发时，凡是“状态、风格、策略、分类、类型、权限级别”这类可枚举数据，优先进入系统字典；凡是“默认值、候选数量、超时、开关”这类单值运行参数，优先进入系统配置；凡是长文本提示词，优先进入 Prompt 模板；凡是模型元数据和凭证来源，优先进入模型管理。

详细口径见：[10-系统枚举治理与公共能力落位](/D:/code/Han/docs/10-系统枚举治理与公共能力落位.md)。

## 18. 分镜视频参考图公网访问

更新时间：2026-07-10

已确认：

- 分镜视频生成为图生视频链路，模型供应商需要访问已选场景图的公网 URL。
- 短剧媒体资产中的场景图必须保存为受控公开文件路径，例如 `/file/public/static-rustfs/{objectName}.jpg`。
- `han-aivideo-ui` 必须将 `^~ /file/public/` 代理到 `han-gateway`，避免客户入口 `:3000/file/public/**` 被 SPA fallback 返回 HTML。
- `han-aivideo` 使用 `HAN_AIVIDEO_MEDIA_PUBLIC_FILE_ORIGIN` 生成供应商可访问的绝对地址；正式值由部署环境注入，不在文档中硬编码外部主机。
- 不建议为供应商单独开放 `9207` 或 `9090` 公网端口；默认通过客户入口暴露受控公开文件路径。
- 匿名 `/aivideo/public/media/{mediaId}/preview` 只允许租户策略为 `PUBLIC` 且已确认的 `SCENE_IMAGE`、`CHARACTER_IMAGE`、`PROP_IMAGE`、`SHOT_TAIL_FRAME`；音频、视频和未确认候选仍必须登录访问。
- 服务端媒体回源只接受规范 `/file/public/{locator}/{fileName}`，外部 URL 仅提取该受控路径；拒绝其他协议、查询串、片段、额外路径层级、反斜杠和编码分隔符，避免 SSRF 与路径绕行。

验证方式：

- 对实际候选文件执行 `curl`，期望返回 `200`、正确图片 MIME 和非零字节数。
- 分镜视频抽屉中的提示词预览应展示完整参考图 URL。
- 远程验证同时检查未授权私有文件不可访问，避免把“能下载”误判为权限正确。
- 安全回归必须验证外部非受控 URL、`..` 路径、公开音视频和未确认图片均被拒绝，规范已确认参考图仍可访问。

官方依据：

- 火山引擎《图片生成编辑（豆包seedream系列模型）》说明 `reference_images` 支持 `None / str / list[str]`，其中 `list[str]` 表示多张参考图 URL，可用于图生图。
- 火山引擎 Seedream 4.0 发布说明强调多图融合、参考生图、图像编辑和主体一致性能力，可用于影视动漫场景、分镜脚本制作和场景设计。
- 当前 Han 实现使用 OpenAI-compatible 图片生成接口时，通过 `image` 字段传递已确认媒体生成的公网参考图 URL；若实际模型配置改为 LAS 算子或其他接入方式，需要在 `han-ai` provider 层做字段映射，不应改短剧业务层。

已落地链路：

- `han-ai`：图片生成请求支持 `referenceImageUrls`，由 provider 转成模型请求参考图输入；这是通用 Han 图片生成能力。
- `han-aivideo`：角色图、场景图生成支持 `referenceMediaIds`，只允许引用当前项目内已确认媒体，后端解析为公网 URL 后传给 `han-ai`。
- `han-aivideo-ui`：`/studio/projects/:id/workbench` 提供已确认角色图/场景图下拉选择、缩略图预览和放大查看；分镜视频抽屉展示当前会参与视频生成的角色/场景锚点。

反哺分类：

- Han 通用能力：图片模型参考图输入、媒体预览 URL 复用、参考图选择组件。
- AI 短剧业务能力：同场景推荐参考、角色/场景锚定提示词、分镜视频参考锚点展示。
- 不属于本轮反哺：自定义参考图上传、外部 URL 输入、SQL 结构变更、部署配置变更、密钥配置变更。

约束：

- 参考图必须来自已确认媒体资产；未确认候选图不能作为后续锚点，避免把错误结果继续放大。
- UI 最多允许选择 9 张参考图，超过后自动截断，避免超过模型输入能力或造成提示词失控。
- 场景图生成时，如果资产文本包含“同一条街道、同一地点、延续、上一场景”等连续性信息，默认推荐上一张已确认场景图作为图片1。
- 角色图生成时，如果该角色已有已确认角色图，默认引用自己的已确认图作为图片1。
- 后续若开放自定义上传或 URL 输入，必须先补安全校验、文件大小限制、MIME 校验、外链可访问性检查和回滚方案。

验证口径：

- 前端页面行为：`cd han-aivideo-ui && .\node_modules\.bin\playwright.CMD test tests/e2e/specs/aivideo-reference-images.spec.ts --project=chromium --reporter=list`
- 前端编译校验：`cd han-aivideo-ui && pnpm build`
- 后端编译校验：`mvn -gs settings.workspace.xml -pl han-api/han-api-ai,han-modules/han-ai,han-modules/han-aivideo -am -DskipTests compile`

回滚口径：

- UI 回滚：移除 `ReferenceImagePicker` 使用，恢复旧的无参考图生成入口。
- 后端回滚：移除 `referenceMediaIds` 到 `referenceImageUrls` 的解析与传递，保留原文生图逻辑。
- 数据回滚：本轮未新增 SQL、未变更表结构；已确认媒体记录不需要回滚。

残留风险：

- 不同 Seedream 模型版本或接入形态对多参考图字段名可能不同；实际线上以当前模型配置和 provider 调用日志为准。
- 参考图越多越容易互相抢主体，默认仍推荐“图片1 为主锚点，后续图片只补充局部细节”的提示词策略。
