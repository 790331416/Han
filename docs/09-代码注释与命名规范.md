# Han 代码注释与命名规范

本文件是 Han 仓库**注释与命名的唯一权威口径**。`.trae/rules/`、`.windsurf/rules/`
下的同类描述属于 IDE 侧镜像，与本文件冲突时以本文件为准。

## 1. 目标

本规范用于统一 Han 前后端代码的注释与命名口径，保证公共模块、业务模块和扩展模块都能做到：

- 注释解释“为什么这样做”“边界是什么”“会影响哪里”，而不是机械复述代码；
- 注释全部使用中文，编码统一为 UTF-8，不允许乱码、错码或不可读文本；
- 命名在同一类对象上完全一致，读到名字就能判断它的层次、职责和读写语义；
- 公共模块优先补齐注释，保证其他模块接入时能看懂、能复用、能扩展；
- 注释与代码保持同步，代码变了必须同步更新注释。

## 2. 总体原则

### 2.1 必须注释的场景

- 公共类、公共接口、公共方法。
- 跨模块复用的工具类、组件、组合式函数、字典加载器、基础配置加载器。
- 复杂业务分支、兜底逻辑、兼容逻辑、缓存逻辑、租户逻辑。
- 容易误用的参数约束、返回值约束、幂等要求、回滚要求。
- 与数据库初始化、升级脚本、运行期兜底三套来源一致性相关的代码。

### 2.2 不应该写的注释

- 纯复述代码表面行为的注释。
- 已经失效、和实际逻辑不一致的注释。
- “临时改一下”“先这么写”但没有上下文的注释。
- 大段无结构说明、无法指导维护的流水账注释。

### 2.3 注释优先级

1. 公共基础模块。
2. 跨模块共享组件或工具。
3. 复杂业务入口。
4. 普通业务页或简单 CRUD。

## 3. 后端注释规则

### 3.1 JavaDoc 适用范围

以下对象必须补 JavaDoc：

- `public class`
- `public interface`
- `public enum`
- `public record`
- `public` / `protected` 方法

推荐格式：

```java
/**
 * 字典运行期兜底注册中心。
 *
 * <p>负责在租户首次访问字典接口时补齐内置字典，保证数据库初始化、
 * SQL 升级脚本和运行期兜底三套来源保持一致。
 */
public class SysBuiltinDictRegistry {

    /**
     * 为当前租户补齐缺失的内置字典。
     *
     * @throws RuntimeException 当数据库写入失败时回滚当前事务
     */
    public void ensureBuiltInDictionaries() {
    }
}
```

### 3.2 控制器与开放接口

- Controller 类要说明“是谁调用、负责什么、不负责什么”。
- 对外接口方法要说明查询条件、幂等性、是否包含运行期兜底逻辑。
- 推荐同时补 `@Tag`、`@Operation`、`@Parameter` 等 OpenAPI 注解，注解描述统一中文。

### 3.3 私有方法与复杂逻辑

以下情况必须补块注释或方法注释：

- 多租户判定。
- 运行期兜底或回退。
- 兼容旧数据、旧模板、旧参数的逻辑。
- 复杂 SQL 组装、复杂查询条件。
- 容易被误删的保护判断。

示例：

```java
/**
 * 统一把空租户视为平台租户，避免运行期插入 null 租户脏数据。
 */
private Long resolveTenantId() {
    Long tenantId = TenantHelper.getTenantId();
    return tenantId != null ? tenantId : 0L;
}
```

## 4. 前端注释规则

### 4.1 Vue 页面

以下内容建议补注释：

- 页面职责说明。
- 组合式状态来源。
- 公共字典、公共配置、回退策略的加载逻辑。
- 流式任务、轮询、媒体预览、跨阶段状态同步。

示例：

```ts
/**
 * 页面不直接维护写死的状态枚举，统一走 `han-ui/src/utils/dict-options.ts` 的
 * 公共字典加载，这样列表页、表单页和详情页可以共享同一套来源。
 */
const { statusOptions, modelTypeOptions } = await loadDictOptionSet({
  statusOptions: { dictType: SYS_NORMAL_DISABLE_DICT },
  modelTypeOptions: { dictType: AI_MODEL_TYPE_DICT }
})
```

### 4.2 TypeScript 工具与组合式函数

公共工具必须写清楚：

- 输入输出约束。
- 失败时是否回退。
- 是否允许空值。
- 为什么放在公共层，而不是业务页里临时实现。

示例：

```ts
/**
 * 根据字典值查找展示标签。
 *
 * <p>统一收敛页面里的 find(...)?label 逻辑，避免每个页面重复维护。
 */
export function findDictLabel(options: DictOption[] = [], value?: string, emptyText = ''): string {
  return options.find((item) => item.value === value)?.label || value || emptyText
}
```

### 4.3 模板层

- 模板层尽量少写注释，避免干扰阅读。
- 只有结构复杂、条件渲染层级深、存在强业务约束时，才补简短注释。
- 模板注释不能替代脚本层注释。

## 5. SQL 与脚本注释规则

- 初始化 SQL、升级 SQL、回填 SQL 必须标明用途和适用范围。
- 新增字典、配置、模板时，要说明“初始化”“升级补齐”“运行期兜底”三者关系。
- 部署脚本、验证脚本要说明依赖环境、输入参数、回滚方式或失败处理策略。

示例：

```sql
-- AIVideo 扩展字典：素材访问策略
-- 说明：用于项目基础配置、设置页和后续媒体权限控制统一下拉来源
```

## 6. 编写要求

### 6.1 语言与格式

- 注释统一中文。
- 段落说明推荐使用 `/** ... */`。
- 单行补充说明可使用 `//`。
- 不允许混用乱码、拼音缩写、不可读英文碎片。

### 6.2 内容要求

每条有效注释至少回答下列问题之一：

- 这段逻辑的业务目的是什么？
- 为什么不能直接简化？
- 这里在兼容什么旧行为？
- 这里的边界条件是什么？
- 这里和哪些公共模块、配置、字典、SQL 有联动？

## 7. 注释落地顺序

当前仓库建议按下面顺序持续补齐：

1. `han-common`、`han-modules`、`han-ui/src/utils` 等公共层。
2. AI / AIVideo 公共配置、字典、模板、工作流、媒体链路。
3. 复杂工作台页面和流式生成页面。
4. 其他普通管理页。

## 8. 检查清单

提交前至少确认：

- 公共模块新增或改动的方法是否补了中文注释。
- 注释是否仍然和代码一致。
- 是否把“兜底来源”“字典来源”“配置来源”写清楚。
- 是否出现复述式废话注释。
- 是否引入乱码或错误编码。
- 新增的类、方法、字段、表、列、环境变量是否符合 §10 至 §12 的命名规范。
- 是否在同一个包内引入了与既有后缀不一致的第二套命名口径。

## 9. 与系统能力的关系

- 系统已经有字典、配置、模板、模型等公共能力时，优先复用系统能力，并在注释中说明复用点。
- 如果因为兼容性或迁移阶段保留了本地 fallback，必须在注释里写明 fallback 的目的和移除条件。
- 修改公共模块时，必须保持可扩展、可复用、可封装，避免把私有业务逻辑硬编码进系统公共层。

## 10. 后端命名规范

### 10.1 类与接口后缀

层次后缀统一使用「首字母大写 + 其余小写」，不使用全大写缩写。
`Po` 在仓库内已经是清一色的这种写法，`Dto` / `Vo` / `Bo` 必须与之对齐，
避免同一个 `domain` 包里同时出现 `SysUserDto` 和 `UserDTO` 这种两套口径。

| 类型 | 命名规则 | 示例 |
| --- | --- | --- |
| 持久化对象 | `<实体名>Po` | `SysUserPo` |
| 传输对象 | `<实体名>Dto` | `SysUserDto` |
| 视图对象 | `<实体名>Vo` | `OnlineUserVo` |
| 业务对象 | `<实体名>Bo` | `SysUserBo` |
| 查询入参 | `<实体名>Query` | `SysUserQuery` |
| 请求入参 | `<语义>Request` | `AiChatRequest` |
| 响应出参 | `<语义>Response` | `AiChatResponse` |
| B 层控制器 | `B<实体名>Controller` | `BSysUserController` |
| A 层控制器 | `A<实体名>Controller` | `ASysUserController` |
| I 层控制器 | `I<实体名>Controller` | `IFileController` |
| Service 接口 | `I<实体名>Service` | `ISysUserService` |
| Service 实现 | `<实体名>ServiceImpl` | `SysUserServiceImpl` |
| Mapper 接口 | `<实体名>Mapper` | `SysUserMapper` |
| MapStruct 转换器 | `<实体名>Converter` | `SysUserConverter` |
| 配置属性类 | `<语义>Properties` | `DeployProperties` |
| 自动配置类 | `<语义>AutoConfiguration` | `WebExceptionAutoConfiguration` |
| 工具类 | `<语义>Util` | `HanStrUtil` |
| 切面 | `<语义>Aspect` | `OperLogAspect` |
| 异常 | `<语义>Exception` | `ForbiddenException` |

`Request` / `Response` 用于「不对应单一实体」的接口入参出参；
能对应实体的一律用 `Dto` / `Vo`，不要两套并用。

### 10.2 方法命名

数据访问与服务层统一使用下列动词前缀，禁止 `get/find/query/list` 混用表达同一语义。

| 操作 | 命名规则 | 示例 |
| --- | --- | --- |
| 按主键查单个 | `select<实体>ById` | `selectUserById` |
| 条件查列表 | `select<实体>List` | `selectUserList` |
| 分页查询 | `select<实体>Page` | `selectUserPage` |
| 新增 | `insert<实体>` | `insertUser` |
| 修改 | `update<实体>` | `updateUser` |
| 按主键删除 | `delete<实体>ById` | `deleteUserById` |
| 批量删除 | `delete<实体>ByIds` | `deleteUserByIds` |
| 存在性判断 | `exists<语义>` | `existsUserByPhone` |
| 计数 | `count<语义>` | `countVisibleSessions` |
| 校验并在失败时抛错 | `require<语义>` / `assert<语义>` | `requireTenantAccess` |
| 兜底补齐 | `ensure<语义>` | `ensureBuiltInDictionaries` |
| 解析并可能回退 | `resolve<语义>` | `resolveTenantId` |

工具类的纯函数不受动词表约束，但同一工具类内部必须自洽。

### 10.3 字段、常量与包

- 字段、局部变量、方法参数：小驼峰，不使用匈牙利前缀，不使用 `_` 前缀。
- 布尔字段不加 `is` 前缀（`enabled` 而不是 `isEnabled`），由 Lombok 生成的
  `isEnabled()` 承担读语义；数据库侧的 `'0'/'1'` 字符标志沿用 `status`、`delFlag` 现有口径。
- 常量：全大写下划线，定义在使用方最近的类里，不要为了「集中」建万能常量类。
- 包名：全小写，不使用下划线和驼峰，按 `com.han.<模块>.<层>` 组织，
  层级目录沿用仓库现状 `controller` / `service` / `service.impl` / `mapper` / `domain.po` /
  `domain.dto` / `domain.vo` / `domain.query` / `config` / `util`。

### 10.4 泛型与类型参数

- 单类型参数用 `T`，键值用 `K` / `V`，返回值用 `R`，多个业务泛型用有意义的名字（如 `ID`）。

## 11. 前端命名规范

| 类型 | 命名规则 | 示例 |
| --- | --- | --- |
| 页面目录 | 小写中划线，页面文件固定 `index.vue` | `system/user/index.vue` |
| 通用组件文件 | 大驼峰 | `DictTag.vue` |
| 组合式函数 | `use<语义>` | `useDictOptions` |
| Pinia store | `use<语义>Store` | `useUserStore` |
| 工具函数文件 | 小写中划线 | `dict-options.ts` |
| 类型 / 接口 | 大驼峰，不加 `I` 前缀 | `DictOption` |
| 常量 | 全大写下划线 | `SYS_NORMAL_DISABLE_DICT` |
| 组件事件 | 小写中划线 | `update:model-value` |
| API 方法 | 与后端动词表对齐 | `selectUserList` |

页面组件名不强制多单词（`vue/multi-word-component-names` 已按仓库的
「目录名 + index.vue」结构关闭），不要为满足该规则批量改名。

## 12. 数据库与配置命名规范

- 表名：小写下划线，模块前缀，如 `sys_user`、`ai_model`、`wf_category`。
- 列名：小写下划线；主键 `id` 或 `<实体>_id`；租户列固定 `tenant_id`；
  逻辑删除列固定 `del_flag`；审计列固定 `create_by` / `create_time` / `update_by` / `update_time`。
- 索引：普通索引 `idx_<表>_<列>`，唯一索引 `uk_<表>_<列>`；
  受逻辑删除影响的唯一约束必须带上租户与删除维度，命名体现出来，如 `uk_sys_role_key_tenant`。
- 环境变量：全大写下划线，机密项在 compose 中一律写 `${VAR:?VAR is required}`，
  **禁止提供明文默认值**。

### 12.1 权限串命名

权限串格式固定为 `<模块>:<资源>:<动作>`，动作后缀沿用若依约定：

| 后缀 | 挂在什么接口上 | 示例 |
| --- | --- | --- |
| `list` | 列表查询 `GET /list`，同时兼作页面菜单的可见性权限 | `system:user:list` |
| `query` | 按主键查详情 `GET /{id}` | `system:user:query` |
| `add` / `edit` / `remove` | 新增、修改、删除 | `system:user:add` |
| `export` / `import` | 导出、导入 | `system:user:export` |

要点：

- 列表接口一律用 `:list`，**不要**用 `:query`。`:query` 只留给详情接口。
- 模块没有详情接口时就不要播 `:query` 按钮，否则是点不开的死权限点；
  `scripts/checks/check_sql_layout.py` 的 `check_button_perms_have_endpoint` 会拦。
- 前端路由 `meta.permission` 必须与后端页面权限串一致，不能各写各的。
- 改动已发布的权限串必须配升级脚本：先给持有旧权限串的角色补授新权限串，
  再下线旧的，保证升级前后可见范围不变。参考
  `sql/upgrades/{postgres,mysql}/20260813_file_perms_alignment.sql`。

## 13. 英文注释中文化的迁移口径

`docs/09` 自始就要求「注释统一中文」，仓库中残留的英文注释属于历史欠账，按下列口径清理。

### 13.1 必须改为中文

- 类、接口、枚举、方法上的 JavaDoc 与 TSDoc。
- 行内 `//` 与块 `/* */` 说明性注释。
- SQL、Shell、PowerShell、YAML 中的说明性注释。

### 13.2 必须保持原样

以下内容不是注释，或改动会产生实际影响，**一律不许动**：

- 代码标识符：类名、方法名、字段名、常量名、包名。
- 日志文案与异常消息字符串：可能被日志检索、告警规则和前端提示依赖，
  语言口径属于独立议题，不在本次注释迁移范围内。
- `@param` / `@return` / `@throws` / `@deprecated` 等标签名本身，只译标签后的描述文字。
- `{@code ...}`、`{@link ...}` 花括号内的内容。
- 第三方引用原文、协议名、错误码、URL、配置键名。
- 测试方法名与 `@DisplayName` 已有的中文描述。

### 13.3 翻译要求

- 译出意图而不是逐词直译；原注释若本身是复述代码的废话，按 §2.2 直接删掉而不是翻译。
- 原注释若与代码实际行为不符，**以代码为准重写注释**，并在提交说明里点出这处不一致。
- 保持 UTF-8 无 BOM 编码，不得引入乱码。

### 13.4 存量偏差的处理方式

命名不一致（如 `DTO` / `Dto`、`VO` / `Vo` 并存）属于存量偏差，
按「碰到即改」推进：改到哪个文件就把该文件所属的一组类名一次改齐，
不做无验证的全仓大规模改名。每一次改名必须同轮跑通编译与受影响模块测试。
