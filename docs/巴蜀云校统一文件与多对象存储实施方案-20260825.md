# 巴蜀云校统一文件与多对象存储实施方案

版本：V1.1  
状态：已确认，进入开发；本方案不等同于已部署  
范围：管理端、校端、H5、Han 文件服务、天翼云 ZOS、后续自建 RustFS/MinIO

## 1. 已确认事实与目标

### 1.1 当前事实

- 生产校端 `sgkt-bashu-oss` 已连接天翼云 ZOS；它使用 S3 兼容协议，不是本地 MinIO 或 RustFS。
- 已确认业务对象存储桶为 `school-lj`；`mysql-lj` 只允许放数据库备份及历史误写文件兼容，禁止再写入业务文件。
- 天翼云 ZOS 的生产服务端地址使用同资源池 IPv4：`http://xinan-1-internal.zos.ctyun.cn`；外网 Endpoint 为 `https://xinan1.zos.ctyun.cn`。
- 管理端 `/file/upload` 已路由到 `han-file`，但生产没有可用 `han-file` 实例，因此返回 503。
- H5 当前没有上传功能；它仅从校端课程接口取得封面、资源、预览和下载地址。

### 1.2 最终目标

```text
管理端 ─┐
校端   ─┼─> Han Gateway ─> han-file ─> S3CompatibleStorageProvider
H5读取 ─┘                                  ├─ 天翼云 ZOS / school-lj
                                             ├─ 自建 RustFS（后续）
                                             └─ 自建 MinIO / 其他 S3 兼容存储（后续）
```

- 只保留一个 `han-file` 文件服务，不按对象存储类型拆出多套文件服务。
- 天翼云 ZOS、RustFS、MinIO 第一阶段共用一个 S3 兼容适配器；真实出现非 S3 兼容供应商时再新增专用适配器。
- 管理端、校端所有新业务文件均通过 `han-file` 写入；H5 只通过 `han-file` 预览和下载。
- 每个文件保存上传时使用的存储配置 ID；切换默认存储后旧文件仍从原存储读取。
- 配置、AK/SK 密文保存在数据库；主密钥只保存在生产服务器的受限 Secret/环境文件，绝不写入 Git、Nacos、接口响应或日志。

## 2. 存储与密钥设计

### 2.1 存储配置

`sys_oss_config` 保存多套存储配置，新增/完善以下字段：

| 字段 | 用途 |
| --- | --- |
| `oss_config_id` | 存储配置 ID |
| `tenant_id` | 租户范围，空代表全局 |
| `config_key` / `config_name` | 稳定标识和中文名称 |
| `provider_type` | 第一阶段固定为 `S3` |
| `endpoint` / `public_endpoint` | 服务端与可选浏览器访问地址 |
| `region` / `path_style` | S3 签名与寻址配置 |
| `bucket_name` / `prefix` | 目标桶与对象前缀 |
| `access_key_ciphertext` / `secret_key_ciphertext` | AES-256-GCM 密文 |
| `key_version` | 加密主密钥版本 |
| `status` | `NORMAL`、`READ_ONLY`、`DISABLED` |
| `config_version` | 客户端缓存失效版本 |

首批配置：

| config_key | 状态 | 桶 | 用途 |
| --- | --- | --- | --- |
| `ctyun-school` | `NORMAL` | `school-lj` | 生产默认写入 |
| `ctyun-mysql-legacy` | `READ_ONLY` | `mysql-lj` | 历史误写业务文件兼容 |
| `rustfs-local` | 后续新增 | 自建业务桶 | RustFS实际部署并通过探针后才可新增 |

### 2.2 当前写入配置

新增 `sys_storage_active`：

| 字段 | 用途 |
| --- | --- |
| `tenant_id` | 主键；一租户一条活动指针 |
| `oss_config_id` | 当前默认写入存储 |
| `version` | 乐观锁版本 |
| `update_by` / `update_time` | 切换审计 |

活动指针与存储配置分离：`NORMAL` 表示可用，活动指针表示新上传写到哪里。这样旧文件所属配置可继续读取，不会被“切换默认存储”误停用。

### 2.3 文件元数据

`sys_file` 增加或使用：

| 字段 | 用途 |
| --- | --- |
| `storage_config_id` | 文件所属存储配置 |
| `object_key` | 对象唯一 Key |
| `school_id` / `biz_type` | 学校与业务归属 |
| `visibility` | `PUBLIC` / `PRIVATE` |
| `checksum` | 完整性校验 |

对象 Key 统一生成，禁止用户控制完整路径：

```text
tenant/{tenantId}/school/{schoolId}/{bizType}/{yyyy}/{MM}/{snowflakeId}_{safeName}
```

### 2.4 密钥安全

- 数据库仅保存 AES-256-GCM 密文和 `key_version`。
- `HAN_STORAGE_MASTER_KEY_V1` 只放 Docker Secret 或权限为 `600` 的服务器受限文件。
- 接口列表只返回脱敏 AK 和全掩码 SK；编辑时密钥留空表示保留旧值。
- 不允许删除仍被 `sys_file` 引用的存储配置；只能先改为 `READ_ONLY`，完成迁移后再停用。

## 3. 动态切换规则

切换入口只保留管理端“OSS 存储配置”页面，Nacos 不作为日常切换来源。

Nacos 仅保存：

```yaml
han:
  storage:
    config-source: database
    cache-ttl-seconds: 30
    temporary-url-seconds: 600
```

切换步骤：

1. 管理员新增或编辑配置，密钥加密入库。
2. 点击“测试连接”：上传唯一探针、读取校验、删除探针。
3. 探针通过后，锁定并原子更新 `sys_storage_active`。
4. 发布缓存失效事件，所有 `han-file` 实例刷新活动配置。
5. 新文件写新存储；旧文件按 `sys_file.storage_config_id`读原存储。
6. 切换失败不改活动指针；随时可指回原配置。

不允许双写 `sgkt-bashu-oss` 与 `han-file`，避免一边成功一边失败产生不一致数据。

## 4. 接口与访问边界

### 4.1 文件服务

```text
POST   /file/upload
GET    /file/{id}
GET    /file/{id}/content
GET    /file/{id}/temporary-url
GET    /file/public/{id}
DELETE /file/{id}

POST   /inner/file/upload
GET    /inner/file/{id}
GET    /inner/file/{id}/temporary-url
```

- `PUBLIC` 文件经 `/file/public/{id}` 访问，例如头像、Logo、课程封面。
- `PRIVATE` 文件必须校验租户、学校、当前身份和业务权限。
- 大文件通过短时签名 URL 或 `han-file` 流式代理下载。
- 前端绝不获取 ZOS 内网 URL、桶名、AK/SK 或永久签名地址。

### 4.2 统一响应

```json
{
  "id": "文件ID",
  "name": "原始文件名",
  "url": "/file/public/文件ID",
  "size": 1024,
  "contentType": "image/png"
}
```

## 5. 三端改造清单

### 5.1 管理端

| 功能 | 当前位置 | 改造方式 |
| --- | --- | --- |
| 个人头像 | `han-ui/src/api/system/user.ts`、`views/user/profile/index.vue` | 保持 `/file/upload`；头像字段保存 `/file/public/{fileId}` |
| 系统品牌 Logo | `han-ui/src/api/system/brand.ts`、`SystemBrandService` | 从服务器本地 `logo.bin` 改为 `han-file`；保留 `/system/public/brand/logo` 兼容地址 |
| AI 聊天图片 | `han-ui/src/api/ai/index.ts` | 已走 `/file/upload`，随 `han-file`恢复自动生效 |
| AI 知识库原始文档 | `han-ui/src/api/ai/index.ts`、`han-ai` | 解析前先内部归档到 `han-file`，持久保存 `fileId` |
| 用户/人员 Excel 导入、工作流 BPMN | 各业务导入接口 | 属于临时解析文件，保持原接口，只做回归测试 |

### 5.2 校端前端

校端前端保留业务上传接口，避免绕过业务关联：

| 页面 | 当前接口 | 后端切换后前端改动 |
| --- | --- | --- |
| `components/courseEditing/index.vue` | `/resourcesFile/upload` | 兼容 `fileId/url`，课程封面回显 |
| `views/reservation/index.vue` | `/resourcesFile/upload` | 兼容 `fileId/url`，预约封面回显 |
| `views/fileMet/index.vue` | `/resourcesFile/upload` | 资源文件保存与回显 |
| `views/knowledge/index.vue` | `/slice/UploadResourceSlice` | 切片资源保存与回显 |
| `views/review/setting.vue` | `/resourcesFile/upload` | 回看资源保存与回显 |
| `views/schoolMet/components/editdialog.vue` | `/common/upload` | 学校图片、Logo、风采图 |
| `views/schoolSet/index.vue` | `/common/upload` | 学校设置图片 |
| `views/schools/components/detailPage.vue` | `/common/upload` | 学校详情图片 |

前端统一要求：上传失败不清空旧文件；重新上传后业务保存成功才删除旧文件；支持上传中状态、文件类型/大小校验和兼容旧响应。

### 5.3 校端后端

新增 `HanFileClient`，使用内部鉴权调用 `han-file`。以下旧 `FileApi`写入链路改造：

| 当前位置 | 用途 | 新业务类型 |
| --- | --- | --- |
| `CommonController` | 学校图片、Logo、风采图 | `SCHOOL_IMAGE` |
| `TbResourceFileServiceImpl` | 课程资源、封面、附件 | `COURSE_RESOURCE` |
| `TbResourceSliceServiceImpl` | 资源切片 | `RESOURCE_SLICE` |
| `TbResourcesSpeechServiceImpl` | 语音资源 | `RESOURCE_SPEECH` |
| 转码输出链路 | 转码结果 | `TRANSCODE_RESULT` |

校端业务表采用加法兼容：增加可空 `han_file_id`。读取优先级：

```text
han_file_id 有值 → han-file
han_file_id 为空 → 旧 sgkt-bashu-oss
```

历史迁移完成前，不删除旧 `businessId/serialId`字段或旧读取逻辑。

### 5.4 H5

H5当前没有上传入口；改造重点是读取：

| 当前位置 | 改造 |
| --- | --- |
| `api/user.ts` | 接收 `fileId` 与受控访问地址 |
| `pages/index/live.vue` | 不再优先使用裸 `fileUrl`；通过 `han-file`获取下载/预览地址 |
| `pages/resource/index.vue` | 图片、文档、音视频统一走 `han-file` |
| `pages/resource/preview.vue` | 短时签名过期后仅自动刷新一次 |

状态约定：空数组显示“暂无资源”；超时才显示“重新加载”；401回登录；403提示无权限；404提示资源不存在；签名过期自动刷新一次。

## 6. 历史 `mysql-lj` 文件

1. 新增 `ctyun-mysql-legacy`只读配置。
2. 盘点 `mysql-lj`：区分数据库备份与历史业务对象。
3. 业务对象复制到 `school-lj`，逐个校验大小和校验值。
4. 回填 `sys_file.storage_config_id`及校端业务 `han_file_id`。
5. 观察期内保留旧对象，人工确认后才允许精确清理。
6. 数据库备份对象永不纳入业务迁移或删除任务。

## 7. 开发、发布与回滚顺序

### 7.1 开发顺序

1. 完成 SQL、密钥加密、存储配置和通用 S3 适配器。
2. 完成 `han-file`上传、读取、临时 URL、配置切换与单元测试。
3. 完成管理端头像、品牌 Logo、AI 文件改造。
4. 完成校端内部客户端、业务表兼容字段和旧读兼容。
5. 完成校端上传页面兼容。
6. 完成 H5资源读取、预览和下载改造。
7. 完成真实 ZOS 联调与全量构建。

### 7.2 后续上线顺序（本轮不执行）

1. 执行加法型数据库升级。
2. 部署 `han-file`但不切校端新写入。
3. 先验证管理端头像、品牌 Logo、AI图片。
4. 部署校端后端、前端和H5，保持校端 `legacy`开关。
5. 按“课程封面 → 学校图片 → 普通资源 → 切片/语音 → H5读取”逐步启用。
6. 验收后停止旧 OSS 新写入；旧读兼容和历史迁移另行收口。

### 7.3 回滚

- 存储切换失败：活动指针指回原配置，任何对象都不删除。
- 校端切换失败：开关切回 `legacy`，新 `han_file_id`保留。
- H5失败：回滚静态资源，校端接口继续返回旧 `fileUrl`兼容字段。
- 管理端Logo失败：保留旧 `logo.bin`直到四端Logo验收通过。

## 8. 联合验收

必须覆盖：

- 管理端头像、系统Logo、AI聊天图片、知识库文件。
- 校端预约封面、课程封面、课件、切片、语音、学校图片。
- H5封面、资源列表、图片预览、文档下载、音视频访问、空态和签名过期。
- 相同文件名不覆盖。
- 中文文件名和大文件。
- 跨租户、跨学校、无权限访问。
- 天翼云上传后切换到RustFS，旧天翼云文件仍可读；切回后RustFS文件仍可读。
- 数据库无明文AK/SK；接口与日志无完整密钥。
- `mysql-lj`无新增业务对象，`school-lj`承接全部新业务对象。

## 9. 本轮边界

- 本文档和后续代码开发均不执行生产 SQL、不部署、不推送。
- 不删除 `mysql-lj`、旧对象、旧校端 OSS 服务或历史业务字段。
- 生产 Region、Path Style、AK/SK权限必须以真实天翼云探针为准，不能根据默认值猜测。
