# 测试与验收手册

## 1. 测试目标

- 统一 Han UI 的端到端执行方式
- 用真实浏览器覆盖登录、菜单、通知、租户、OSS、AI 等关键链路
- 页面级健康回归必须检测内部接口错误，而不是只看页面壳子

## 2. 当前正式测试口径

### 2.1 当前通过状态

- `small`：主链路通过
- `medium`：主链路通过
- `full`：主链路通过
- `full AI`：专项回归通过

### 2.2 已通过主链路

- `small`：登录、通知中心、任务调度、系统核心页、页面级健康回归
- `medium`：登录、租户、开放平台、OSS、工作流、页面级健康回归
- `full`：登录、代码生成、AI 模型、AI 应用、AI 对话、页面级健康回归、Full AI 专项

### 2.3 诚实边界

- `AI Graph`：未开发
- `Embed Chat`：未开发
- `pdf/docx` 自动解析：部分开发

## 3. 95 固定验证顺序

1. `small`
2. `medium`
3. `full`
4. `full AI` 专项

## 4. 每档最小验证

- 运行时能力接口
- 登录链路
- 页面级健康回归

## 5. 补充验证范围

### 5.1 small

1. 登录并进入首页
2. 打开通知中心，检查未读数、单条已读、全部已读
3. 打开任务调度列表和日志页，执行一次新增与立即执行
4. 检查系统管理与日志监控核心页面可达

### 5.2 medium

1. 在 `small` 清单基础上继续
2. 打开租户、租户套餐、租户配额
3. 打开开放平台并验证应用生命周期操作
4. 打开 OSS 配置并执行真实上传
5. 打开工作流定义、实例、待办、已办

### 5.3 full

1. 在 `medium` 清单基础上继续
2. 打开代码生成，验证导入、预览、下载
3. 打开 AI 模型，检查配置与连通测试
4. 打开知识库、Prompt、MCP、应用、聊天、Token 页面
5. 验证应用详情、结构化元数据和聊天链路

## 6. Playwright 规范

### 6.1 目录

```text
han-ui/
  tests/e2e/
  output/playwright/
```

### 6.2 推荐执行

```bash
cd han-ui
pnpm build
pnpm test:e2e
```

### 6.3 关键约束

- 默认使用 `PW_WORKERS=1`
- 每个 spec 建议使用独立输出目录，避免 artifact 冲突
- 页面级健康回归必须捕获 HTTP 错误、业务错误、页面异常和控制台异常

## 7. 留痕要求

- 记录部署提交
- 记录验证命令
- 记录通过项、失败项和边界项
- 记录本轮是否动过 SQL、部署文件或运行时代码

## 8. 发布前最小验收集

- `small`：登录、通知中心、任务调度、页面级健康回归
- `medium`：登录、租户、开放平台、OSS、页面级健康回归
- `full`：登录、代码生成、AI 模型、AI 应用、AI 对话、页面级健康回归、Full AI 专项回归

## 9. 结论

测试文档只保留这一份正式手册作为总入口。阶段性验证报告、一次性排障记录和旧计划全部进入 `docs/archive/`。
