# Han Cloud 优化分析

## 1. 本轮已收口的内容

### 部署与基线

- 新增统一部署层级配置：`han.deploy.tier`
- 新增运行时能力接口：`/system/runtime/capabilities`
- 前端登录页和侧边栏开始按后端运行时层级降级显示
- 补充 `settings.workspace.xml`，解决仓库构建依赖本机固定 Maven 仓库路径的问题
- 三档 compose 统一引入 `HAN_DEPLOY_TIER` 和 `HAN_INNER_AUTH_SECRET`

### 安全边界

- 网关剥离外部伪造的用户头和内部鉴权头
- `@InnerAuth` 补齐请求签名校验链路
- `@HttpExchange` 内部调用自动附带内部鉴权头
- 登录失败锁定键改为 `tenantId + username`
- 数据权限处理器开始消费登录态中的部门范围

### 系统能力

- 运行时能力接口开始返回 tier、默认模块、可选中间件、功能开关
- `small` 补进调度服务
- `medium` 补进工作流服务
- `han-open` 的 Docker 端口与应用端口收敛为 `9205`

## 2. 当前仍需整改的重点

### P0

- `job/open/system/tenant/workflow` 关键写接口仍需补齐统一权限注解
- SSE 通知链路还没有完成真正的鉴权与按用户未读收口
- 菜单与权限命名体系仍未完全统一

### P1

- 业务路由还没有彻底切到“后端菜单 + 运行时能力”双重驱动
- OSS 配置后端闭环仍待补齐
- 开放平台应用管理和 OAuth2/SSO 仍需要从占位实现走向持久化实现

### P2

- AI 模块后端壳层需要继续补齐
- 代码生成器虽然已有代码，但部署方式和运行开关还未完全纳入主链路
- Kafka / Elasticsearch / 观测套件目前仍是可选外挂能力，未纳入默认 compose

## 3. 推荐下一步

### 第一优先级

- 统一核心控制器权限注解
- 补 OSS 配置后端能力
- 修 SSE 通知的鉴权和未读模型

### 第二优先级

- 把前端业务路由正式切到后端菜单接口
- 补开放平台应用管理 CRUD 与密钥重置
- 为 `medium/full` 补更完整的接口契约测试

### 第三优先级

- 完成 AI 后端壳层
- 让代码生成器进入可部署、可探测、可测试状态
- 为 Kafka / Elasticsearch / 观测套件设计单独的外挂部署说明
