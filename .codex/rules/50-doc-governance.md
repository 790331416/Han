# 文档与知识治理规则

## 1. 文件定位

- 本文件用于约束规则文件、说明文档、运行手册和经验沉淀的组织方式。
- 当任务涉及文档新增、规则拆分、知识归档或 `.codex` 演化时，必须读取本文件。

## 2. 正式入口

- `docs/` 是 Han 唯一正式文档入口。
- `docs/06-牛马协作总规则.md` 是唯一正式规则文档。
- `README.md` 是项目正式大入口。
- `.codex/` 是协作资产，不是正式文档入口。

## 3. 组织原则

- 根规则文件只放全局原则、通用门禁、交付要求和协作资产边界。
- 语言、框架、目录专属规则可以放 `.codex/rules` 或路径级 `AGENTS.md`，但不得与正式规则冲突。
- 提示词模板、模式卡、评估集、运行手册、部署手册分目录管理，命名清晰，能版本追踪。
- 规则要短句、祈使句、结构化，避免长篇叙事。
- 示例比空话有效，约束比口号有效。

## 4. 文档增量维护

- 文档优先在原有文档基础上补充、修订、扩展。
- 开发相关内容优先补充到开发手册。
- 测试相关内容优先补充到测试与验收手册。
- 部署和 95 相关内容优先补充到部署手册或运维与95环境手册。
- 规范相关内容优先补充到 `docs/06-牛马协作总规则.md`。
- 新增文档前必须先检查是否已经存在承载同类内容的文档。
- 禁止为同一主题反复新建最终版、新版、补充版、说明版等重复文档。

## 5. 外部内容处理

- 外部链接不是规则本体，关键要求要复制进仓库内文档，避免引用失效。
- 官方资料、外部规范、行业方案只作为依据，不直接替代仓库内规则。
- 对外部资料有时效性时，优先查官方文档并标明来源。

## 6. 记忆闭环使用方式

- `corrections.jsonl`：记录用户对行为、规则、输出方式的纠正。
- `observations.jsonl`：记录仓库现状、流程痛点、重复问题。
- `learned-rules.md`：把多次出现的问题提炼成新规则候选。
- `evolution-log.md`：记录每次规则工程化变更、结构调整和落地结果。

## 7. 命名策略

- 文档正文默认中文。
- 正式文档文件名使用中文。
- 规则资产文件名和目录名优先使用稳定 ASCII 命名。
- 内容中文化与路径 ASCII 化不冲突；前者服务团队阅读，后者服务工具稳定。

## 8. 同步要求

- 任意涉及文档结构的变更，必须同步更新 `docs/index.md`。
- 任意涉及 SQL 落位的变更，必须同步更新 `sql/README.md`。
- 任意涉及部署结构的变更，必须同步更新部署手册。
- 任意发布到 95 的变更，必须同步更新测试与运维手册中的验证口径。
